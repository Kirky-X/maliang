# research/ —— 测量驱动的规则修订目录

> 本目录收**自己测量、可以推翻自己规则**的过程记录：某条既有规则被真实测量推翻或修正时，把问题、方法、数据与落档过程记在这里。它是修订的证据来源，不是规则本体——规则仍然只存在于各自的法律文件里。来源：tastemaker 仓 research/ 目录的过程纪律（「自己测量、而不是猜测」），2026-10 吸收，条目体例自研。

## 条目标准（四条，缺一不入）

1. **真实问题**：某条既有规则在真实产出中造成了可观察的坏结果，说得出是哪条规则、什么坏结果。
2. **真实方法**：实测（DOM 取 computed 值 / 渲染量取 / 脚本测量）、读源码、或可复现的测量过程——写清量了什么、怎么量的；不收「凭经验觉得」。
3. **数据带语境**：数字必须附视口宽度、样本对象、量取方式，让下一个人能复核。
4. **落地留痕**：结论改了哪个文件的哪条规则，附 PR / commit 链接（外部研究标注外部仓链接）；尚未落地的条目标注「未落地」并说明卡在哪。

**不是把 PR 描述复述成独立研究**：条目的主体是问题、方法与数据，落地只是末行。只有 PR 描述、没有方法与数据的条目是变更日志，不收——判据是：换一个人拿同样的方法与数据，能否独立得出同样结论。

## 与两套既有记忆的分工

| | decisions 账本（DESIGN.md） | feedback-ledger | research/（本目录） |
| --- | --- | --- | --- |
| 管什么 | **单项目**设计决策（为什么选这个方向 / 定这个值） | **单项目**协作规则的沉淀与晋升 | **跨项目**、证据驱动的一般性规则修订输入 |
| 生命周期 | 随项目 DESIGN.md | 随项目账本，白名单晋升 | 仓库级，永久 |
| 与规则的关系 | 解释本项目产物 | 约束协作行为 | 修订规则本身的证据 |

研究条目与既有规则相抵时，它是修订该规则的证据来源；修订动作本身走对应文档的更新流程（正文改动 + 来源标注带日期与数据），不在本目录里改成新规则。

## 条目索引

### 2026-10 · 区块间距实测：间距阶梯「 generous 上限 96px」是假设值

- **问题**：生成的落地页读作局促，每个区块都没拿到应有的视觉权重。条件反射的修法是「把 padding 调大」——那是猜测，不是研究。真实问题：一份公认体面的高级落地页，区块间距**实测**是多少？
- **方法**：以 make.design 为具名参照，1280px 视口下用 DOM 自省读真实 computed padding / gap 值——量活页面的计算值，不是看截图估。
- **数据**：单侧区块 padding **64–192px**，不是一个统一值；相邻区块边界间隔均值 **~165px**，范围 **112–248px**；分隔几乎全靠留白本身（多数区块背景透明，不靠交替底色做分隔）；padding 按区块权重刻意不均——轻量 trust bar 全部 padding 合计 ~68px，最重的区块合计达 320px。
- **推翻了什么**：外部样式表的间距阶梯把区块 padding 上限钉在 `space-24`（96px）当「generous 档」，且要求全项目取**一个**值。两条都被实测直接推翻：真实参照的最重区块用到该上限的两倍以上，且按区块权重变值而非定死一档。这解释了为什么生成页「明明在阶梯内却读作局促」——阶梯自身的上限就是假设值，不是测量值。
- **落地**：外部仓新增 128/160/192px 档、把区块间距改写为按权重分层（衔接区块 space-12–16 / 常规区块 space-16–24 / 关键区块 space-32–48，桌面边界间隔目标 ~120–250px，显式不适用于应用壳）、新增 spacing 反 slop 检查。tastemaker 仓 PR #48。
- **对本仓的启示**：landing 型页面按区块权重分层给间距、关键区块可达常规档两倍以上，与 spacing 指南「过量留白再削减」的程序互补——先用过量值探下限，再按权重分层收敛。maliang 自身的区块间距档尚未做同类实测，待有真实产物样本后按本目录标准立条。
