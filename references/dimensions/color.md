# 颜色规范

> 规范层。颜色的**使用规则**(原则)。192 产品类型的具体调色板查询在 [`color-palettes.md`](./color-palettes.md);最终 RGBA+HEX 硬值在产物层 [`examples/ui-markdown/token.md`](../../examples/ui-markdown/token.md)。本文件不含具体色值,只讲规则。

## 1. 60-30-10 配色比例

- **主色 60%** — 大面积背景/容器
- **辅助色 30%** — 次要表面/分区/卡片
- **强调色 10%** — CTA/关键操作/焦点状态

明确三色角色,避免某种颜色过突出或压抑其他。三色比例失衡是界面"花"的首要原因。

## 2. 中性色平衡

中性色(白/灰/黑梯度)承担 60-30 主体,给品牌色留出 10% 强调空间。中性色按明度梯度**成体系**(如 50..900 九阶),而非零散取值。中性梯度不稳,品牌色再准也压不住。

## 3. 品牌色扩展

以单一品牌色为根,通过调明度/饱和度派生完整梯度(brand-50..brand-900)。不要为不同状态引入第二种品牌色——状态靠**同色相的明度/饱和变化**表达,不靠换色相。

### 档位 → 用途(9-Shade 映射)


| 档位 | 缺省用途          | 说明                                             |
| ---- | ----------------- | ------------------------------------------------ |
| 50   | 浅底/选中底色     | 最浅一档,大面积 tinted surface                   |
| 100  | hover 底          | 表面悬停时的 tint,比 50 深半档                   |
| 200  | badge/chip 底     | 浅色分类标签、徽章底                             |
| 300  | focus ring/边框   | 非文本 UI 元件档,对相邻背景 ≥ 3:1                |
| 400  | placeholder/禁用  | 弱信息文本(仍须满足各自对比度下限,见第 8 节)     |
| 500  | 主按钮/主 CTA     | 品牌锚点档,通常按"白字在其上达 AA"校准           |
| 600  | hover(实色按钮)   | 500 加深一档(暗底可反向取亮)                     |
| 700  | pressed           | 按下态,比 600 再深一档                           |
| 900  | 正文/图标         | 最深一档,品牌色文字用                            |

- 交互三态固定走 500→600→700(基线/hover/pressed),方向由亮暗模式决定,但三档**必须单调**,不跳档。
- 800 不设独立缺省用途:需要中间档时在 700 与 900 之间插值,不进本表。
- 图表/数据可视化把 100-700 当"同色相深浅序列"用(序列顺序 = 档位顺序),不再引入第二色相。

### OKLCH 派生 hue 旋向(防发灰)

> 同为 web-design-pascalorg 思想中文自研

用 OKLCH 派生 brand-50..brand-900 时,**只动 L、恒定 h 与 C 会让梯度发灰**——感知色度在极浅与极深段天然衰减,浅档发白、深档发闷。修正手法是让 hue 沿色相环做小幅定向旋转("扇形"梯度):

- 每档 h 偏移 2-4° 以内,变亮方向与变暗方向相反:以 brand-500 的 h 为轴,往 100/50 方向逐档 +h,往 700/900 方向逐档 −h(或整体反向,但全站一致)。
- **全梯度累计旋转 ≤ 20-30°(色阶派生约束)**:从最浅档到最深档的 hue 总偏移超过 20-30° 就读作**另一种颜色**,不再是同色的深浅。逐档 2-4° 的设定已在此界内(九档约 16-32°);派生时若想加大角度,先核总旋角,超界即回退——改动 L/C 补明暗差,不加转角。(该上限归属色阶派生语境;单配对的文字色旋转口径见第 9 节,两者不通用)。
- 两端档位的 C 适度补偿:浅档微升 C 防发灰,深档微升 C 防发闷,中档不动。
- 判定顺序:恒定 h 派生后先肉眼查浅档是否发灰——发灰先调 h(每档 2-4°),h 转完仍灰再动 C;禁止一步大幅调 C 掩盖。

## 4. 避免纯黑/纯白

- 文字最深 ≠ 纯黑,用极深灰(接近黑、非纯黑),降低对比刺眼感
- 背景最亮 ≠ 纯白,用极浅灰(接近白、非纯白),减轻视觉疲劳

纯黑/纯白仅用于刻意的高对比场景(如 OLED 纯黑底、纯白摄影底)。

## 5. 暗色模式独立设计

暗色**不是**亮色的简单反色。暗色模式下:

- 背景层级靠**提亮**(深灰梯度,非纯黑叠加),用表面 elevation 区分层而非靠纯黑
- 文字靠**降饱和**(纯白刺眼,用浅灰)
- 强调色饱和度适当下调,避免暗底过刺;高饱和色仅小面积点缀

语义 token 通过主题映射切换明暗,而非每处硬改。

- **跨模式不变清单**:明暗切换时保持**状态色与功能色的色相语义**、字阶、间距、组件形状不变——用户重建心智模型的成本靠这些锚点压住;允许变的只有表面/文字的明度映射与强调色饱和度(按上文下调)。外部原文(nothing-design)连强调色也跨模式不变,maliang 收敛为「色相不变、饱和可调」:下调后必须复验第 8 节对比度。(收敛为 maliang 口径)。
- **白底图像压暗**:亮色内容切到暗色模式时,白底/浅底内容图(截图、图表、证件照)需微压暗或加暗色衬底——原始白底在暗环境中"发光"刺眼;图表类优先用暗色 token 重绘,照片类用亮度滤镜降档

### 暗色派生脚本挂接


design-md 暗色场景可走确定性派生:`scripts/design-md.py derive-dark`(纯标准库)从 [`color-palettes.md`](./color-palettes.md) 的亮色行出发,按固定规则派生暗色行——**品牌色保留**(不换色相)、**表面色固定 slate 系**(不从品牌色派生)、**Ring 按对暗底对比度 ≥ 3:1 自动选**(品牌色组内择优,均不达标则确定性提亮 Primary)、**已是暗色的行直接命中不重派生**;每行输出 `_mode_derivation` 溯源字段记录每列处理方式。产物仍须过第 8 节对比度校验,脚本结果不豁免校验。

### 色场节制(color fields)

节与节之间**换整场底色**是最强的色彩动作——它替代分隔线、卡片与背景装饰,直接给页面分章。规则:

- 每个色场配自己的 ink(文字色):禁浅色 ink 上彩场、禁 muted 灰当彩场正文
- 场际边界用 hard line(硬切换),不渐变——渐变边界读作"没对齐"
- 相邻两场的明度差要足够,拉不开就是"页振"(页面在闪)
- 场序像章节:open strong(强开场)→ rest(静场)→ surprise(反差场)→ close dark(深色收尾)
- 实测锚:强站的整场底色中位 2 种/页;0 种是白纸,3+ 种即花

### World-tint 中性 ramp(按产品世界选 tint)

中性色不是纯灰——按产品归属的世界给整条 ramp 一个极低饱和的 tint(表面永不读作"一个颜色"):工具/技术 → **graphite**;纸/木/食/手作等人文世界 → **warm**;夜/天/水等冷世界 → **ink**。**App 与 dashboard 的表面一律用中性档,世界只出现在 accent/图表/moments**;落地页可把表面向世界多染一档。

**Accent from world**:无真实品牌色时,accent 从世界取——warm 世界配 amber/coral/ember;冷世界配 cobalt/teal/sky;natural 配 moss/sage;**紫蓝系默认回避**(品牌真是紫才用)。accent 压满屏幕的百分之几(主操作/选中态/一个关键数字),文字压 accent 须过 4.5:1,不够就加深或改深色文字。**暗色主按钮优先用 ramp 内 off-white 底+深色文字**,accent 留给更小处(选中态/关键数字)——比彩色按钮更显"有意"。

### 叠加链禁令

优先显式色值,禁半透明叠加链——alpha 叠层让对比度变成上下文相关,验收不可传递(一层改透明度,下面所有配对全变);确需叠层时先算合成色再落 token。

## 6. 功能色(语义固定)

| 语义色  | 角色            | 约束               |
| ------- | --------------- | ------------------ |
| success | 成功/正向       | 跨页面永远同一色相 |
| warning | 警示/提醒       | 跨页面永远同一色相 |
| danger  | 错误/破坏性操作 | 跨页面永远同一色相 |
| info    | 中性提示        | 跨页面永远同一色相 |
| link    | 链接/可点击     | 跨页面永远同一色相 |

功能色语义全局一致:success 永远绿、danger 永远红,不因页面换色。用户靠色相识别语义,换色相即破坏识别。

### 数据状态色三纪律(状态色编码数据值时)

状态色(success/warning/danger)用于编码**数据值**(指标好坏 / 趋势 / 超标)时,只做三件事:

1. **只上数值本身**——着色对象是那个数字或它直接对应的图形标记,不是整行
2. **标签与行背景不上色**——标签保持中性次级色,行 / 卡背景保持表面色;状态靠值说话,背景上色会把单点异常放大成整行告警,读作装饰而非数据
3. **趋势箭头继承数值色**——↑↓ 箭头与它修饰的数值同色,不另起一套箭头配色

图表场景的落地判据在 [`../vocabulary/charts.md`](../vocabulary/charts.md)「数据状态色着色判据」;它与该篇「颜色只用于编码」的分工也写在那里——那条管图表编码通道(类别 / 顺序 / 发散)的选择,本节管**着色落点**(值 / 标签 / 背景 / 箭头)。与第 3 节档位表不冲突:状态色沿用功能色色相,不引入第二套色相。

## 7. 状态色(叠加在功能色上)

| 状态     | 表达                      |
| -------- | ------------------------- |
| default  | 静止基线                  |
| hover    | 悬停(轻微提亮/加深)       |
| pressed  | 按下(反向微调)            |
| focused  | 键盘聚焦(常配 focus ring) |
| disabled | 不可用(降透明度,非换灰)   |
| selected | 选中(提饱和或加底色)      |

状态色是功能色基础上的明度/饱和微调,**不引入新色相**。disabled 统一降透明度而非换灰色,保留语义可读性。

## 8. WCAG 对比度强制

> 本节为颜色相关的对比度硬性规则。完整 WCAG 规则(含 prefers-* 偏好)见 [`accessibility.md`](../meta/accessibility.md)。Accessibility 为 CRITICAL 优先级(见 [`rules-priority.md`](../meta/rules-priority.md)),不可被任何颜色美学覆盖。

### 阈值表

| 文本类型             | AA(最低) | AAA(目标) |
| -------------------- | --------- | ----------- |
| 正文(< 18pt / 14pt bold) | 4.5:1     | 7:1         |
| 大文本(≥ 18pt / 14pt bold) | 3:1       | 4.5:1       |
| 非文本(UI 组件 / 图形) | 3:1       | —           |

**暗色模式对比度上限(防眩)**:对比度只设下限会催生"纯白字压纯黑底"(21:1)的刺眼组合——暗色正文对比度建议 ≤15:1,纯白(#FFFFFF)正文在近黑底上应降档为浅灰;小图片/图标的背板与底色对比同样适用此上限。上限与下限之间才是暗色的舒适区。

### 颜色配对强制项

- `color-text-primary` 与 `color-bg-primary` 配对**必须**通过 AA(4.5:1 正文)
- `color-text-secondary` 即使作为辅助文字,只要承载信息,也必须 ≥ 4.5:1
- `color-text-disabled` 不豁免对比度,需 ≥ 3:1(保证可识别)
- `color-border` 与背景对比度 ≥ 3:1(用于表单 / 输入框边框识别)
- `placeholder` 文字 ≥ 4.5:1,不可用 `text-gray-300` 凑数

### 状态色对比度

| 状态     | 对比度规则                                       |
| -------- | ------------------------------------------------ |
| hover    | 不可降低对比度(提亮通常降低对比度,需校验)     |
| pressed  | 不可低于 default 的 90%                          |
| focused  | focus ring 与背景对比度 ≥ 3:1                    |
| disabled | 文本对比度仍 ≥ 3:1(不豁免)                    |

### 暗色模式对比度

暗色模式下对比度更易不达标(浅灰文字 on 深灰背景):

- 暗色背景的 `color-text-primary` 不可用纯白(`#fff`),但对比度必须 ≥ 4.5:1 → 用 `#f7f5f2` 或 `#e5e5e5` 一类浅灰
- 暗色强调色饱和度下调,但对比度仍需 ≥ 3:1(大文本 / UI 组件)
- 暗色模式下应优先 AAA(7:1),因暗色背景上视觉疲劳更明显

### 功能色对比度

功能色(success/warning/danger/info)作为信息载体时:

- success 绿色 on 白底 ≥ 4.5:1
- warning 黄色 on 白底常不达标(需用深一档 amber / orange,而非 yellow)
- danger 红色 on 白底 ≥ 4.5:1
- info 与品牌色同源,继承品牌色对比度

### 自动校验

- design-md Phase 3 Lint 阶段:`npx @google/design.md@0.4.0 lint` 自动计算每个组件 `backgroundColor` / `textColor` 配对的 WCAG 对比度,低于 AA 触发 warning
- preview 阶段 Pre-Flight Check:扫描所有文字与背景配对,违反 = 硬性失败
- 工具:WebAIM Contrast Checker / Chrome DevTools Contrast Ratio 检查器

### 实测对比度标注范式(自标值必须可复算)

任何色板 / token 表给「对比度」标注时,标**合成并实测后的值**,不标意图值或透明度声明:

- **半透明前景先合成再测**:`rgba(255,255,255,.38)` on `#000` 合成后是 `#616161`,实测 **3.39:1**——不是「白字 21:1 打 38 折」的任何直觉数;凡透明度参与的前景,对比度声明一律以合成色为准
- **自标值会被复算**:nothing-design tokens 自标 `#666666` on `#000` 为 4.0:1,实算 **3.66:1**——引以为鉴。标注范式(色值 + 背景 + 比值)使偏差可被机械复核,写错即暴露;不标注或标虚数,则错值永远不会被发现
- 标注格式:`#616161 · vs #000 = 3.39:1`(值 · 背景 = 比值),逐档附在灰阶 / 色阶表行尾

产物层 [`../../examples/ui-markdown/token.md`](../../examples/ui-markdown/token.md) 的对比度列按本范式执行。两处比值均经 WCAG 公式复算核实。

## 9. 对比度两个逃生舱(过不了 AA 时的两条合法路径)

> 第 8 节的阈值是硬门;本节是**过门的手法**——不牺牲语义色相、不把界面涂成深色块,把单个配对的对比度做够。与 [`../interface-design/craft-discipline.md`](../interface-design/craft-discipline.md)「One accent」分工:那条管强调色的**总量**节制(颜色是稀缺资源),本节管在不增加视觉重量的前提下把**单个配对**做达标。

### 逃生舱一:翻转对比(badge / pill / tag 的默认处理)

彩底白字要过 4.5:1,底色必须非常深——满页深饱和 badge 会抢走它们不配拥有的注意力。默认反着做:**深色字 + 浅色 tint 底**。品牌色最深档(900)做字、浅档(200)做底,轻松过 AAA,保住语义色相,安静待在层级里。status pill / tag / badge 一律按此默认(即第 3 节档位表 200 档做底、900 档做字的既定用途);只有该元素**本身就是页面主行动**时,才允许实色深底。

### 逃生舱二:跨色相文字旋转(彩底上的次级文字)

深色彩板上的次级文字,只推明度会一路推到近白,与主文字拉不开层级。改向**感知亮度峰值**借对比度:色相环上青(180°)/ 品红(300°)/ 黄(60°)三处人眼感知最亮,把文字色相向最近峰值**小幅旋转**,可在保持「有颜色、是次级」的同时凑足比值(深色面板上反向同理,向蓝 / 绿 / 红的暗峰旋可压暗)。

maliang 口径(自研,外部原文无数值上限):

- **单处旋转 ≤ 30°**:超过读作换了颜色,不再像同一块面板的次级文字
- **旋转后必须实测对比度**(按第 8 节标注范式),不凭「看起来亮了」通过
- 20-30° 总量上限属**色阶派生**语境(第 3 节),不适用于本手法;文字旋转是单配对操作,只受单处 ≤ 30° 约束

### 不扩充声明

外部原文的配色构造顺序(查库 → 映射 → 派生)maliang 已机制化(第 3 节档位映射 + 第 5 节暗色派生脚本 `scripts/design-md.py derive-dark`),不重复扩充。

## 10. 跨色相调和(色轮几何)

第 3 节管**单色相内**的梯度派生(即单色系方案);本节管**跨色相**搭配——需要第二个色相时的选择依据。跨色相调和不是任选,色相环上的角度关系决定张力与和谐度:

| 方案 | 相对基色的偏移 | 张力 | 适用 |
| ---- | -------------- | ---- | ---- |
| 单色系 | 0°(明/饱和变化) | 无 | 默认首选,最稳(第 3 节) |
| 邻近色 | ±30° | 低 | 次级分区/分组底色,和谐不抢戏 |
| 互补 | 180° | 最高 | 只给 CTA/关键强调,**禁止大面积对撞** |
| 分裂互补 | +150° / +210° | 中高 | accent 选型的常用折中:有互补的醒目,少一半冲突 |
| 三角 | +120° / +240° | 中 | 图表分类色/多状态标记,活力且均衡 |
| 四角 | +60° / +180° / +240° | 中高 | 信息密度高的仪表盘,须严守面积纪律 |

- **面积纪律**:每引入一个新色相,它的面积上限就降一档。第二色相默认 ≤30%(即 60-30-10 的次级位),第三及以上只做点缀级(<10%);跨色相数量越多,越要回到 60-30-10 的锚上。
- **冷暖对比**:暖色视觉前进、冷色后退。冷色大面积 + 暖色点睛是默认安全结构(冷底上暖 accent 天然醒目);反转(暖底冷点)需要刻意设计且更难压住。同一界面内冷暖两域各管一头,不要让两类同面积对峙。
- **同时对比**:相邻色相互相推挤感知——互补色直接相邻会双方显得更饱和刺眼;中性灰块会被周边色相"染"上对方的余像。缓解:互补色不直接贴邻,中间隔中性色带;灰阶面板与大色块相邻时,检查灰块是否读作偏色。
- **与功能色的撞位检查**:调和出的 accent 色相不得与语义功能色(§6)读作同义——accent 离 danger 红 / success 绿太近会被读成错误/成功状态。落定前先比对 accent 与四个功能色的色相差,过近即换偏移。
- **确定性求解**:基色 + 方案 → 各偏移色相的三档前景色与配对矩阵,走脚本 `py -3 scripts/verify.py palette-solver --bg <hex> --hue <基色相> --harmony <方案>`(方案:complementary / split-complementary / analogous / triadic / tetradic;缺档显性化返回非零)。色相几何是查找表,不交给模型手算。

## 11. 感知对比 APCA(WCAG 之外的参考值)

第 8 节的 WCAG 对比度是**门禁**,本节不替换它。APCA(Lc)是感知修正参考:同样 4.5:1,深底浅字与浅底深字人眼感受不同,WCAG 给同一个数,APCA 给两个不同的数。

- **语义**:Lc 带符号——深字浅底(BoW)为正,浅字深底(WoB)为负,量程约 ±108;**极性不可交换**,绝对值越大感知对比越强。
- **为什么需要参考**:WCAG 对低对比区间偏松(浅灰小字过 4.5:1 的线但读不清,APCA 会给更严的判),对暗底纯白又系统性高估(21:1 的数字暗示"超安全",感知上刺眼——即 §8 暗色 ≤15:1 上限的感知依据)。
- **参考级别**(按元素的感知需求选档,取绝对值):

| Lc | 用途 |
| ---- | ---- |
| ≥ 90 | 长文正文首选 |
| ≥ 75 | 短段落/内容文本下限 |
| ≥ 60 | 大文本(≥18pt 或 ≥14pt bold) |
| ≥ 45 | 大号加粗文字/图形 |
| ≥ 30 | 非文本 UI 组件下限 |
| < 15 | 不可读(仅装饰/禁用) |

- **落点**:①暗色模式舒适区标定——正文建议 |Lc| 75-90,替代"越大越好"的直觉;②"过线但难读"的二次校验——小字/灰字 WCAG 压线通过但拿不准时,查 APCA 是否 ≥ 75。
- **工具**:库函数 `scripts/maliang_common.py` `apca_Lc_hex(文字 hex, 背景 hex)`(APCA-W3 0.1.9 常量,实测锚点:`#000000` on `#ffffff` = 106.04,`#ffffff` on `#000000` = -107.88)。未进硬门禁:preview/lint 阶段仍按 §8 WCAG 判,APCA 结果仅人工决策用。

## 12. 色相选择的场景映射

按产品类型查 [`color-palettes.md`](./color-palettes.md) 成品表是首选;本节是**无表可查或自定义品牌色**时的推理起点:先定色相域,再派生梯度(第 3 节),最后过对比度门(第 8 节)。

| 场景气质 | 色相域(HSL/OKLCH 色相,度) |
| -------- | -------------------------- |
| 信任/稳定/金融/科技 | 蓝 210-240 |
| 成长/健康/自然/环保 | 绿 120-160 |
| 活力/餐饮/运动 | 橙红 10-40 |
| 创意/灵性/奢侈 | 紫 270-300 |
| 乐观/注意/能源 | 黄橙 40-60 |
| 清洁/冷静/医疗 | 青 180-200 |
| 中性/专业/极简 | 中性灰 + 单点缀 |

- **映射是起点,不是终点**:行业惯性色相域内竞品趋同,品牌辨识度靠域内偏移 ±15-30°(与第 3 节 hue 旋向口径一致:仍在同色域内)。
- **只定色相域,不定明度饱和**:长时阅读/工具类场景禁高饱和大面积(刺眼,见第 5、8 节);情绪倾向靠色相表达,明暗轻重交给场景定。
- **文化差异核查**:红/白/金等色的语义随市场反转(喜庆 vs 危险、纯洁 vs 哀悼),面向多市场的产品先核目标市场的色相语义,单一市场按本地共识;映射表默认西文语境。
- **落定前过三道检查**:与功能色撞位(第 10 节)、对比度门(第 8 节)、暗色模式降饱和复验(第 5 节)。
