# 字体规范

> 规范层。字体的**层级、行高、字重、字族规则**。具体字号/行高硬值在产物层 [`examples/ui-markdown/token.md`](../../examples/ui-markdown/token.md)。

## 字号层级(6 阶)

移动端推荐 6 阶(对应 display / title / subtitle / body / caption / overline):

| 阶  | 角色   | 推荐(pt) |
| --- | ------ | -------- |
| H1  | 大标题 | 24       |
| H2  | 标题   | 18       |
| H3  | 副标题 | 16       |
| H4  | 正文   | 14       |
| H5  | 说明   | 12       |
| H6  | 标注   | 10       |

阶梯原则:相邻阶差 ≥2pt 保证视觉可区分;不超过 6 阶(米勒 7±2,层级过多即失去层级意义)。

## 行高

| 场景        | 行高                 |
| ----------- | -------------------- |
| 标题(≤18pt) | 字号 + 8pt(紧凑)     |
| 正文(≥14pt) | 字号 × 1.4~1.6(舒适) |

标题行高紧凑以突出,正文行高宽松以可读。同一字号的标题与正文用不同行高策略。

## 字重策略

| 字重         | 用途            |
| ------------ | --------------- |
| 400 regular  | 正文            |
| 500 medium   | 强调正文/次标题 |
| 600 semibold | 标题/按钮       |
| 700 bold     | 大标题/数字     |

优先用**字重对比**代替字号对比做层级——避免仅靠字号大小区分,字重 + 字号双维度对比更清晰。

## 字族

- 中文:苹方(PingFang SC)
- 英文/数字:SF Pro / Inter

不超过 2 个字族(性能 + 视觉一致)。中英混排时中文走中文字族,英文/数字走西文字族,数字可单独用等宽或特色字体突出(价格、统计值)。

## 字距(字号的函数)

字距不是固定值,是字号的函数:**大字负字距、小字微正**。同字族放大后字距视觉偏松,display 级适度收紧(如 -0.02em ~ -0.03em);小字号(标注 / 说明)微放松提升可辨性。任何固定 `letter-spacing` 必在某档出错(与 [`ai-tells.md`](../meta/ai-tells.md) 第 2 节 `tracking-tight` 滥用 Tell 同源)。

**CJK 口径(必须遵守)**——负字距源自拉丁排版,中文是均匀方块字,整体负字距破坏均匀感:

- 中文标题**不做整体负字距**;紧凑感靠字重与字号,不动字距
- 负字距仅限两处慎用:①标点挤压(全角标点占位收紧);②中西混排的**西文片段**内部
- 中文正文与标注维持默认字距或微松,禁 `tracking-tight` 一刀切

> 来源：apple-design §15（tracking is size-specific / Dynamic Type）思想，2026-09 吸收；CJK 本地化为 maliang 自研口径。

## CJK 字体加载纪律(硬性)

> 与上方「字族」节的 CJK 口径衔接:字族决定**用什么**(苹方 / 思源),本节决定**怎么加载**。来源:hue 仓的 chinese-typography 口径,2026-10 吸收。

- **正文 / UI 一律系统字体栈**:中文正文与界面文字走系统栈(苹方 / HarmonyOS Sans / 平台默认),**不引入中文 Web 字体**——CJK 单文件 5–20MB,首屏阻塞;思源黑体 / 思源宋体**全量引入同样违规**,不是"开源就可以引"。
- **例外仅限创意 / 品牌 Hero 标题短语**,且三条同时满足才允许:① `text=` 子集化(只含实际渲染的字符,每个请求几 KB);② `font-display: swap`;③ 系统栈 fallback 必须写出。方向卡 / 预览页的「字体策略」栏如实写「标题(子集化)+ 中文系统栈正文」,不写「思源黑体」冒充全站字体。
- **预览页自身同样受约束、无豁免**:选择外壳与说明区用系统栈,装饰中文字体只用于 mockup 标题短语。
- **字数与体积自检**:引入任何 CJK 字体文件前先答"它加载多少字节、挡不挡首屏";答不出 = 不引。加载性能口径见 [`../meta/performance.md`](../meta/performance.md)。

## CJK 字重陷阱(硬性)

> 上方「字重策略」的四档(400 / 500 / 600 / 700)是**西文口径**;中文字体的实际可用字重窄得多,照抄四档会落进伪合成。来源:hue 仓的 chinese-typography 口径,2026-10 吸收。

- **多数中文字体只有 400 / 700 两档**,中间字重(500 / 600)是浏览器**伪合成**(或直接落回最近一档),不是真字重——中文界面写 `font-weight: 500` 常常什么也没发生,或得到发虚的合成笔画。
- **苹方是特例但要记准**:有 Ultralight–Semibold 各档,**没有 Bold**——写 `700` 实际落到 600。跨平台(Web / HarmonyOS / Flutter)行为不一致时以平台实际渲染为准,不假设数值字重存在。
- **中文标题 / 强调写 500 / 600,不写 `bold` / 700**:层级靠**字号 + 真存在的字重档**建立;需要更强时加字号或换字族,不叠伪合成。
- **自检**:交付前在目标平台实际渲染,对比"写的字重"与"渲染的字重";用 `document.fonts` / 平台字体 API 核对该字族是否真有该档,别只信 CSS 声明。
- 与上方「字重策略」的关系:西文 / 数字仍按四档走;中文段落按本节降档——**中英混排时同一元素内不强行统一字重值**,各按自己的可用档取值,视觉重量对齐即可。

## 盘古之白(中英 / 数字混排间距)

中文与西文 / 数字混排时,字与字之间的视觉密度不均,需要**手工插入半角空格**补足呼吸:

- **中文 ↔ 数字**:「共 12 个」「第 3 页」——数字两侧加空格
- **中文 ↔ 西文单词**:「使用 Figma 设计」「导出为 PNG」——西文两侧加空格
- **数字 ↔ 单位**:「128 px」「30 GB」「3 kg」——数字与单位之间加空格
- **例外(不加空格)**:`°` 与 `%` 等紧贴符号——「25°C」「99.9%」不加;全角标点(`，。、：；！？「」`)前后不加——标点自身已含间距
- **不加的地方**:代码标识符、URL、文件路径、版本号(`v0.3.6`)、CSS 值内部

交付前逐处检查正文、标题、按钮文案与数据标签;这是排版细节项,见 preview-checklist 5.10。来源:hue 仓的 chinese-typography 口径,2026-10 吸收。

## display 字体候选池与禁用清单(西文)

> **两层口径分工(防内部矛盾)**:display 选型由 [`ai-tells.md`](../meta/ai-tells.md) 第 11 节反射字体清单管辖(命中不自动违规,走其第 0 节豁免总则);本文件"字族"节的 SF Pro / Inter 默认管辖**正文 / 工作马**,不因 display 禁用清单被连带否定。本节候选池是 §11"按受众世界选字"替代路径的弹药库——先从受众 / 品牌世界反推气质,再入池对号,不是从池里抽签。来源：landing-page-guide-v2,2026-09 吸收。

**display 候选池(12 款,按气质分组)**,用于标题 / display 层:

| 气质 | 候选 |

## 文字透明度梯度(层级靠透明度)

正文基于同一文字色,通过透明度梯度表达层级,而非为每层定义独立颜色:

| 透明度 | 角色 |
| ------ | ---- |
| 100%   | 主文 |
| 80%    | 次文 |
| 60%    | 辅助 |
| 40%    | 占位 |
| 20%    | 装饰 |
| 10%    | 底纹 |

一套透明度梯度统一所有层级,降级时只调透明度不换色。

## 行长与行高

行长规则(单行可读宽度上限):

| 文种 | 行宽上限 | 备注 |
| --- | --- | --- |
| 西文正文 | ≤ 80 字符 | 衬线正文可略放宽 |
| 中文正文 | 35-42 个全角字 | 按全角字换算,非"80 字符"直译 |

- 衬线正文的行高比无衬线**略增**(升部 / 降部更长,需要更干净的行间通道)
- 大段正文颜色适当变浅(避免深色大块文字压迫),但 MUST 保持 WCAG AA(4.5:1)对比度——变浅以不跌破对比度下限为前提

> 来源：frontend-design-anthropic 行长 / 衬线行高思想，2026-09 吸收；中文 35-42 全角字换算为 maliang CJK 口径。

## 斜体降部安全(西文片段)

display 级标题把行高压到 `leading-none`(1.0)时,含**降部字母**(`y g j p q`)的西文斜体词会被裁底。规则:

- display 行高 1.0 且强调词为**西文斜体**时,强制行高 ≥ 1.1,并在包裹元素加 `pb-1` / `mb-1` 预留降部空间(Web CSS 语境;Harmony / Flutter 对应为文本容器留 padding 余量)
- 中文场景该规则条件化为「西文斜体片段」:仅当中文标题内嵌**西文斜体强调词**时适用;中文本身不用斜体做强调,层级靠字重与字号

交付前逐个检查 display 标题中的斜体词是否含降部字母。来源：taste 斜体降部思想,2026-09 吸收;CJK 条件化为 maliang 口径。

## 随用户字号缩放(Dynamic Type 等价)

尊重用户系统字号设置:布局**随文字缩放**,放大字号不破版。

- Web:间距与容器尺寸用 `rem` / `em` 相对单位,不用固定 `px`,文字随根字号缩放时间距同步
- HarmonyOS:字号用 `fp` 单位,组件尺寸随字号资源联动
- Flutter:经 `TextScaler` / `MediaQuery` 派生相对尺寸,禁写死像素字号

层级链(字号 → 行高 → 字距 → 间距)按比例联动,而不是只放大字号。来源：apple-design Dynamic Type 思想,2026-09 吸收。
