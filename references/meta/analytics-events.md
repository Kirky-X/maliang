# 埋点事件规范 —— 命名 / 漏斗 / 基线比对

> 规范层。迭代段的数据锚点:事件怎么命名、核心漏斗怎么定义、改版前后怎么比对,回答"这版变好没"。分工:[`ux-rules.md`](ux-rules.md) 管界面规则,本文只管埋点规范,事件名不约束界面文案。执行时机:`design-md` 建档时定事件表,`redesign` 改版前导基线、改版后比对。

## 1. 事件命名规范

- 事件名 kebab-case,动词在前、宾语在后:`cta-click`、`signup-submit`、`order-success`;禁中文、空格、驼峰混用
- 每事件属性 ≤ 8 个,属性名 snake_case;统一属性:`page`(页面标识,同 ui-markdown 文件名)、`component`(触发组件 id)、`ts`(时间戳,SDK 自动附)
- **隐私红线**:不采集个人敏感数据(证件 / 健康 / 生物特征 / 精准定位 / 明文联系方式);用户标识只存不可回溯的匿名 id;每个采集项须能一句话说清用途

## 2. 核心漏斗三件套

| 环节 | 事件模式                            | 例                  |
| ---- | ----------------------------------- | ------------------- |
| 曝光 | `<目标>-view`                       | `pricing-view`      |
| 交互 | `<目标>-click` / `<目标>-submit` | `pricing-cta-click` |
| 成功 | `<目标>-success`                    | `signup-success`    |

漏斗定义 = 路径 + 时间窗 + 成功判据:`曝光 → 交互 → 成功,窗口 ≤ 7 天,成功 = success 事件 ≥ 1`;每条漏斗对应 DESIGN.md `users:` 块的一条 journey(见 [`spec-schema.md`](spec-schema.md))。

## 3. 与 UI 的对应关系

- 关键转化路径的**每步都要有事件锚点**:CTA / 表单 / 主操作在 ui-markdown 组件意图头标注 `event: cta-view / cta-click / submit / success`
- 无锚点的转化步骤 = 漏斗断点——上线后说不清"用户在哪一步流失"
- `critique` 发现流程缺陷时,同步检查该步有无锚点可供上线后量化验证

## 4. 与 redesign / ui-graph 的关系(基线比对)

- **改版前**:按本文格式导出埋点基线(事件清单 + 各漏斗近 30 天转化率),随改版方案存档
- **改版后**:同名事件比对基线;redesign"永不静默改动"已列埋点事件名改名——必须改时新旧双写过渡
- `ui-graph` 哈希基线回答"哪些页面变了",埋点基线回答"变化后数据有没有断";两个基线 + decisions 账本构成迭代段证据链
