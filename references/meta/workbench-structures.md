# 工作台结构分类学 —— 11 种结构与品类→结构映射

> 规范层。回答 [`surface-modes.md`](surface-modes.md) 不回答的问题:一个数据型产品**围着什么转、每种转法怎么死**。surface-modes 管页面访客模式层(视觉级联),本文件管产品结构层(定义与存活),两者互补不重复。**本文件的品类→结构映射表是内部工具数据,永远不给用户看**——它是当用户说出一个品类名时,你用来直接断言具体方案的地图,不是给用户的选择菜单。来源:mouse-lin/finesse-brief 仓的 workbench-types.md 与 system-domain.md §6,2026-10 吸收。

## 0. 结构判定前置

先判域(系统域判据:「一共有 N 个 X」成立、有多角色多模块),后判结构。**域决定你被允许问几个问题,结构决定你要建什么。**多数真实产品是「主 + 副」两结构:主结构拥有 hook 与首屏形态;副结构贡献一两个频道/模块。**三个结构 = 三个工作台**,说清楚并让用户选先建哪个——合并版没有单一 hook、单一时刻。

| 域 | 结构 |
| --- | --- |
| 个人域主导 | `cycle` · `ledger` · `state` · `runbook` · `care` |
| 跨域(一人与四十人同构,只差数据底座规模) | `feed` · `operation` |
| 系统域主导 | `pipeline` · `registry` · `console` · `monitor` |

结构与域的关系是倾向不是规则:个人知识库是 `registry` 单用户;一家三餐台是 `care` 两读者。以域判定为准绳。

## Part I · 个人域主导

### 1. `cycle` —— 系统可计算的外在节律
- **引擎**:锚点日期 + 已知周期。系统永远知道你在哪一段。
- **Hook**:你在第 N 天/段,因此今天…(state)。
- **数据底座**:锚点日期一次录入偶尔修正。**零载入成本最高——输入容忍度低时的首选结构。**
- **留存**:阶段自己翻页,明天 hook 自然不同,用户不动也成立。
- **死法**:锚点永远没被录入,N 不存在,满屏退化为通用建议。**day 1 必须是锚点请求,别无其他。**

### 2. `ledger` —— 每日小记录,价值在累积曲线
- **引擎**:重复小记录;兑付在形状,不在单行。
- **Hook**:今天 X / 目标 Y,差 Z(delta)。
- **数据底座**:每日 user 写入,**最贵的底座**——每个决策都为降低单次成本。
- **留存**:曲线本身,靠 Review 频道兑付。**无 Review 频道的 ledger 是数据录入杂役,第三周被扔。**
- **死法**:输入债。三天缺口让曲线显得废掉,人连回来面对它的勇气都没。**必须配「免补录回归句」。**

### 3. `state` —— 今日状态,无需累积
- **引擎**:昨天/此刻转成可读判定 + 一个后果。
- **Hook**:昨晚/今天你是 X,所以 Y(state→imperative)。
- **数据底座**:一条近期读数(可穿戴/屏幕时间/天气,常可推导或一次点按)。
- **留存**:判定每天自动变。**近零输入可用,低容忍用户的最好结构。**
- **死法**:判定天天一样。对策:让后果分句具体可行动,判定带真数字不带形容词。

### 4. `runbook` —— 为今天开的处方序列
- **引擎**:一份计划(生成或编排)化成今日清单。
- **Hook**:今天这 N 件事(imperative)。
- **数据底座**:计划(一次)+ 完成点按(每日,便宜)。
- **死法**:清单每天一样,那闹钟免费干这活。对策:今日清单必须对昨日的完成作出反应——那个反应*就是*产品。

### 5. `care` —— 另一个存在的状态
- **引擎**:主体不是用户:宠物、婴儿、植物、爸妈。
- **Hook**:它/他第 N 天,今天该…(state+imperative)。
- **数据底座**:生日/领养日(免费一次)+ 轻观察。**记录别人比记录自己容易得多**,输入容忍度全类最高。
- **死法**:只有里程碑没有每日打开理由(疫苗驱虫一年四次,那是日历)。对策:配 `ledger` 副结构(体重曲线/投喂记录)给出每日面。
- **5.A · 分叉——主体有自己意志吗?** 猫/婴儿/植物不可反对;学龄孩子/青春期/爸妈可以,约束反向:
  - 数据来源三选一:她看着并记录(是监控)×;他自己记录(那他是有打开理由的第二读者,须 hook 也值得他开)×/√; **只记结果不记过程、按周不按天(通常的正确答案)**。
  - 此分叉中,hook 陈述**进度不陈述亏欠**,记录**默认主体可见**。判定与修法见 [`day-two-blacklist.md`](day-two-blacklist.md) D13。

## Part II · 跨域

### 6. `feed` —— 外部信息经筛选翻译
- **引擎**:一条外部流,替他过滤,用人话重写。
- **Hook**:今天这 3 条 + 一句人话解读(imperative)。
- **数据底座**:外部源而非用户。听着简单恰是陷阱:没有用户数据,**筛选本身就是全部产品**。写入方几乎必然是 integration,`data-floor.md` §3 依赖规则全力适用。
- **死法**:随处可得的通用内容。对策:feed 绑到他持有的东西(持仓 / 行业 / 备考科目)——这通常把它变成 `feed + ledger` 复合,那通常是对的。
- **硬边界**:永不发明内容,材料必须来自真实来源。

### 7. `operation` —— 钱与货在动
- **引擎**:进出、增减。
- **Hook**:今日流水 X · 库存告警 Y · 今天建议 Z(delta+imperative)。
- **数据底座**:钱与量,不可协商,**DEPTH 门槛相应残酷**。
- **死法(个人规模)**:记账比记事本贵。对策:给记事本给不了的(下雨建议主推热饮 / 损耗提醒 / 竞品价格)——**建议不只是算术,是这个结构存在的全部理由**。
- **死法(系统规模:ERP/进销存/电商后台)**:库存数字从第一周起就不准,之后没人再信页上任何数。对策:把对账时刻(盘点/日结)定义成真实模块,hook 显示「未对账 N 笔」而不是装作总数是真的。

## Part III · 系统域主导

### 8. `pipeline` —— 对象在有序阶段中推进
- **引擎**:一组对象,各处在 N 个有序阶段之一,由人往前推。
- **Hook**:N 个待推进 · M 个卡在 {阶段} 超 K 天 · 今天先看这几个(delta+imperative)。
- **首屏**:看板,列=阶段。**不是表格**——表格首屏 + 状态列的 pipeline 是在翻译中丢了结构,页面会看起来很好却什么也不做。
- **数据底座**:stage(user 写入但便宜,一次拖动)+ last_activity_at(**system** 写入,任何活动记录存储时顺手写,见 `data-floor.md` Move 0)。超期 derived 免费。系统域最便宜的高价值底座。
- **死法**:没人拖卡片,全停在第一阶段,看板成谎言,结论条汇报小说。对策:阶段变化挂到已有动作(记跟进→问是否推进);阶段 ≤5;把「多久没动」放卡面上,让陈旧的看板 visibly 陈旧而不是悄悄错。

### 9. `registry` —— 可检索的对象目录
- **引擎**:一批值得留下的对象,之后能找到。CRUD+详情+搜索。
- **死法一**:空着开始空着继续。day 1 必须是导入路径或两字段创建表单。**空目录不是满目录的小号版,是另一种没用的产品。**
- **死法二**:变成只有搜索才到的地方——那不是工作台,是带皮肤的数据库。
- **留存**:全十一结构最弱,必须显式设计:配 `pipeline`/`feed` 副结构给个每日理由,或让 hook 指向维护工作(「12 条缺标签」「8 条超一年没动」)。

### 10. `console` —— 一群在跑、可介入的东西
- **引擎**:N 件自己运行、偶尔需要你的事。启停配置重试。
- **首屏**:卡片/行阵,**按「需要关注」排序**,失败置顶,永不按字母或创建时间。
- **数据底座**:几乎全 system 写入(运行结束落一行),系统域最便宜的底座。
- **死法一**:全绿的墙。没有东西失败时,每次打开同一屏,信息量为零。hook 必须上增量与成本(「比上周慢 40%」「花费已超预算 80%」),让好日子也有东西读。
- **死法二(定义期最常见)**:要管的舰队还不存在。day 1 必须是带可用两字段路径的「建第一个」。

### 11. `monitor` —— 指标与异常,可下钻
- **引擎**:从别处聚合的数字 + 判定对错的阈值。
- **首屏**:几个大数字,然后异常列表,然后趋势。异常列表不是可选项——它是 monitor 与壁纸的分界。
- **数据底座**:几乎全 integration,**最容易被 spec 得很美、上线发空的结构**。每个数字写明来源系统与 exists_today(`data-floor.md` §3)。
- **死法一**:只有总数没有异常,变壁纸。对策:每个数字带阈值或对比,hook 点名称最严重那个。
- **死法二**:不可下钻。数字提出问题页面答不了,用户回源系统查三次后不再来。**L2 必须从 L1 每个数字可达**,这是结构要求不是优化。

## 组合规则(主 + 副)

- **主结构拥有 hook 与首屏形态**。pipeline 首屏是表格、ledger 配 imperative hook,都是「结构在翻译中丢失」——页面会看起来很好,这就是为什么必须在此判定。
- **弱结构靠对的副结构救,不靠加模块**。care 没有每日面要的是一条 ledger 频道,不是四个知识频道;registry 没有每日理由要 feed/pipeline 副结构,不是更好的搜索框。
- **`registry` 与 `monitor` 几乎永不单飞**:空目录和总数墙两个已知留存洞,都由副结构补。
- 已知好组合:增肌台 ledger+runbook · 毛孩子台 care+ledger · 姨妈台 cycle+state · CRM pipeline+registry · Agent 控制台 console+registry · 智慧工厂 monitor+console · 电商后台 operation+pipeline · 知识库 registry+feed · 审批/OA pipeline 单结构。

## 判不准时:问消失一个月会丢什么

| 丢了才知道 | 结构 |
| --- | --- |
| 不知道自己在哪个阶段 | `cycle` |
| 曲线断/记录没了 | `ledger` |
| 不知道今天状态怎么样 | `state` |
| 不知道今天该干嘛 | `runbook` |
| 错过消息 | `feed` |
| 它/他的成长没人记 | `care` |
| 账对不上 | `operation` |
| 不知道哪些卡住该推谁 | `pipeline` |
| 东西找不着 | `registry` |
| 不知道昨晚谁挂了 | `console` |
| 出事没人第一时间知道 | `monitor` |

然后用输入容忍度与结构底座对表:个人域有弃用史的用户配 `ledger` 主结构是已知碰撞(单键降成本,或主结构换 state/cycle、ledger 退副);系统域 `monitor`/`feed` 主结构的数字全靠未建成的集成,同一个碰撞的企业版(集成是真的,或数字离场)。这里决定免费,上线日发现不免费。
