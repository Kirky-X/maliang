# 文案指南 —— UI 文案规范与语气体系

> 规范层。Content 是 redesign 9 维度审计的第 5 维度(见 [`redesign.md`](../commands/redesign.md) 维度 5)。本文定义 UI 文案的语气、格式、反模式与场景模板。与 [`ai-tells.md`](./ai-tells.md) 第 4 节 Content Tells 联动。

## 1. 语气体系

### 三级语气模型

| 语气级别 | 适用场景 | 特征 | 示例 |
| --------- | -------- | ---- | ---- |
| 正式 | 金融/法律/政府/合规 | 完整句式、敬语、无缩写 | "请您确认以下信息" |
| 专业友好 | SaaS/工具/电商(默认) | 简洁直接、适度亲切、无废话 | "确认支付" / "已保存到草稿" |
| 轻松活泼 | 社交/娱乐/儿童/创意 | 口语化、emoji 可选、有个性 | "搞定!✨ 你的作品已发布" |

**强制规则**:
- 同一产品内语气级别一致,不可混用(如设置页正式 + 首页活泼)
- 默认"专业友好",除非 [`product-reasoning.md`](./product-reasoning.md) 推理出其他级别
- 错误/危险操作用更正式语气(即轻松产品也用"操作失败,请重试"而非"哎呀出错了~")

## 2. CTA(行动号召)规范

### 格式

- **动词 + 名词**:明确告诉用户做什么
- ≤ 4 个中文词 / ≤ 3 个英文词
- 避免模糊动词("了解更多" → 改为具体动作)

### 示例对照

| ❌ 弱 CTA | ✅ 强 CTA | 原因 |
| --------- | --------- | ---- |
| "提交" | "开始免费试用" | 具体价值 |
| "了解更多" | "查看定价方案" | 明确目标 |
| "点击这里" | "下载年度报告" | 描述内容而非位置 |
| "确定" | "保存更改" | 说明动作后果 |

### 层级

- **主 CTA**:每屏 ≤ 1 个,用 primary 按钮样式
- **次 CTA**:≤ 2 个,用 secondary/tertiary 按钮样式
- 多 CTA 并列时须区分重要性(见 [`principles.md`](./principles.md) 改版案例 #30)

## 3. 数字格式

### 真实风数据(反 AI Tells)

- **禁止**整数凑数:`100+ Users` / `1M+ Revenue` / `99.9% Uptime`(见 [`ai-tells.md`](./ai-tells.md) §4)
- **使用**带尾数:`2,847 users` / `127.3K downloads` / `99.97% uptime`
- 大数字用千分位分隔:`1,024` 非 `1024`
- 百分比保留 1-2 位小数:`99.7%` 非 `100%`

### 单位

| 场景 | 格式 | 示例 |
| ---- | ---- | ---- |
| 文件大小 | 自动换算 | "2.3 MB" / "458 KB" |
| 时间 | 相对时间优先 | "3 分钟前" / "昨天 14:30" |
| 货币 | 符号 + 数字 | "¥128.00" / "$9.99" |
| 距离 | 米/千米自动 | "350 m" / "12.5 km" |

## 4. 状态文案模板

### Loading 状态

```
正在加载[对象]…
正在处理你的请求…
```

- 超过 10 秒显示进度百分比或预估时间
- 骨架屏优先于 spinner(见 [`principles.md`](./principles.md) 第 14 定律)

### Empty 状态

```
[情感化短句] + [具体说明] + [CTA]
```

示例:
- "还没有消息" → "暂无新消息" → "去发现页看看"
- "购物车空空如也" → "你还没添加任何商品" → "去逛逛"

### Error 状态

```
[错误原因] + [可执行建议]
```

| ❌ 弱错误 | ✅ 强错误 |
| --------- | --------- |
| "出错了" | "网络连接失败,请检查 Wi-Fi 后重试" |
| "404" | "页面不存在,可能已被移除" + [返回首页] |
| "服务器错误" | "服务暂时不可用,通常 2 分钟内恢复" |

**禁止**:
- 技术术语暴露给用户("NullPointerException" / "SQL syntax error")
- 无建议的纯否定("操作失败" → 加"请检查网络连接后重试")
- 责备用户("你输入了错误的密码" → "密码不正确")

## 5. 反模式(禁止清单)

| 反模式 | 为什么禁止 | 替代 |
| -------- | ---------- | ---- |
| Lorem ipsum 残留 | LLM 截断信号(见 [`llm-behavior.md`](./llm-behavior.md) §4) | 用具体场景化文案,哪怕虚构也要具体 |
| "现代设计"等空泛词 | 无信息量,LLM 认知捷径 | 描述具体特征:"8px 网格 + 单强调色" |
| 双重否定 | 增加认知负荷 | "无需注册" 非 "不是必须注册" |
| 感叹号滥用 | 每句都感叹 = 无感叹 | 仅庆祝/成就场景用(发布成功/升级完成) |
| 内部术语 | 用户不懂业务名词 | "草稿箱" 非 "暂存区" |
| 过长提示 | > 2 行用户不读 | 拆为标题 + 一行说明 |

## 6. 信息层级

- **h1**:每页仅 1 个,≤ 12 中文 / ≤ 7 英文词(见 preview-checklist 5.10)
- **h2**:章节标题,≤ 20 中文 / ≤ 12 英文词
- **h3**:子区块标题
- **不跳级**:h1 → h2 → h3,不出现 h1 → h3
- **label**:表单标签用名词短语(非句子),必填标记用 `*` 放标签后

## 7. 中英混排

- 中英文之间加空格:"使用 React 框架" 非 "使用React框架"
- 数字与中文之间不加空格:"共 128 项" 非 "共 128 项"
- 专有名词保持原大小写:"GitHub" 非 "github" / "Github"
- 中文用全角标点,英文用半角标点

## 8. 文案自检程序(Copy Self-Audit)

> 交付前对页面上**每个可见字符串**(标题 / 眉标 / 按钮 / 正文 / alt / footer / 错误信息)逐条重读,不是抽样抽查。来源:taste-skill §4.9。

程序:

1. 逐串重读所有可见文案(含 alt 文本与 footer),不跳读
2. 标记四类问题:

| 问题类          | 特征                            | 示例                     |
| --------------- | -------------------------------- | ------------------------ |
| 语法残缺        | 半句、缺主语宾语、读不顺         | "更智能的,你的选择"     |
| 指代不明        | "它 / 这个"查无所指              | "它让一切更简单"(它 = ?) |
| AI 幻觉式俏皮话 | 自以为妙、在具体产品里落空的句子 | "优雅的空无"类           |
| 装深思 LLM 腔   | 排比、格言腔、否定转折           | "不是工具,而是伙伴"     |

3. 拿不准就改写成**朴素功能句**——说清这是什么、对用户有什么用
4. 原则:**AI 俏皮文案比无聊文案更糟**——无聊的功能句只输在平淡,俏皮的坏句子输在信任
