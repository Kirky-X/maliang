# 数据底座门禁 —— 首屏那句话凭什么成立

> 规范层。`surface-modes.md` 管页面访客模式层(视觉级联),本文件管**定义层**:首屏/hook 区承诺的每一条数据,必须有字段、有写入方、有冷启动台词。数据条款可以是好设计,也可以是一句没有字段支撑的漂亮话——本门禁只管后者。与 [`ai-tells.md`](ai-tells.md)(视觉层黑名单)分层,与 [`numbered-gates.md`](numbered-gates.md) G29 衔接(交付前拦)。来源:mouse-lin/finesse-brief 仓的 hook-engineering.md,2026-10 吸收。

## 0. 何时过本门禁

产物是**数据型界面**时必过:首屏含数值、进度、榜单、结论条、指标卡、倒计时,或空态之外承诺"今日 X / 目标 Y"。纯内容站(文章 / 作品集 / 落地页)不适用;`persuade` 页面的信任数字(用户数 / 评分)同样适用——它也是数据条款。

设计阶段(design-md Phase 0a)写 DESIGN.md 时判型并过门禁;交付阶段(preview)按 G29 复核结论条。

## 1. 合法 hook 形态与密度底线

| 形态 | 句式 | 适合 |
| --- | --- | --- |
| **State** | 你现在是 X,所以 Y | 周期 / 状态 / 台账 / 控制台 |
| **Delta** | 今天 X / 目标 Y,差 Z | 记账 / 经营 / 监控 / 看板 |
| **Imperative** | 今天该做 X | 计划 / 清单 / 待办 |

密度底线:个人域 1–2 个变量值;系统域 2–4 个分句,构成固定 = **一个进度/总数(带对比)· 一件今天要处理的事(带数量)· 可选一个成本或对比**。超 4 个分句 = 统计条不是 hook;少于 1 个变量 = 幸运签(见 §3 测试)。

## 2. 绑定表(每条数据条款必填,有空格即不批准)

每个 hook 分句写一行,不许只在脑里过:

| 字段 | 读什么(它产出哪个分句) | 写入方 | 何时写 | 第一天空数据时 | 断连/跳过日 |
| --- | --- | --- | --- | --- | --- |

判定规则:

- **读什么**:分句映射不到字段 = 这句话没有东西在计算。这是本类失败的全部形态——日记缺一项和数据库缺一列,死法一样。
- **写入方**:见 §3。每行 `user` 都是一笔税,要数数;一个 hook 里两行 user 通常多了一行。
- **何时写**:必须是某人一天里真实的时刻(保存跟进记录时 / 每次运行结束),不是"按需"。
- **第一空**:见 §5。禁 `--`、禁空表、禁零、禁编造演示数。
- **断连/跳过日**:见 §6。最常见的静默 bug:把昨天的数当今天的渲染。

绑定表随 DESIGN.md 的决策表落库(数据型产品的 `constraints:` 块)。

## 3. 四种写入方

| 写入方 | 含义 | 成本 | 陷阱 |
| --- | --- | --- | --- |
| `user` | 人打字或点选 | **spec 里最贵的东西** | 数它。系统域里九模块每模块三个 user 字段 = 一份没人答应干的全职录入 |
| `derived` | 读时从其他字段算(星期→推日、距今→超期、目标−实际→缺口) | 免费 | 只和输入一样真。输入是个没建成的集成,derived 是虚构不是免费 |
| `system` | 系统在某件已发生动作的副作用里写(运行结束、拖卡片、存记录) | 免费 | 几乎不会失效,**这是要设计去的方向**(§4 Move 0) |
| `integration` | 另一个系统供给(支付回调 / 模型用量 / 设备上报 / ERP 同步) | **字段只有当那个集成真建了才存在** | spec 里最常见的谎:「从 ERP 来」却无 API、无负责人、无日期 |

**规则**:hook 里任何 `integration` 字段必须写明来源系统与**今天是否已存在**。今天不存在的,数字离开 hook,进 depends_on——留在一个空态可承受的模块里。首屏发布日渲染空白,比 spec 里任何别的错都先失去用户。

## 4. 字段要不到输入时的五步(按顺序走,先穷尽便宜的)

- **Move 0 · 挂在正在发生的动作上(系统域最重要的一步)**。没人会填「最后联系时间」,但销售会写跟进记录——`last_activity_at` 由 system 在保存跟进时顺手写。对照表:最后联系时间←存跟进记录;当前阶段←拖看板卡片;是否发货←扫码出库;运行成败←运行结束落一行。**多数好的系统域 hook 全靠这一步建成**。
- **Move 1 · 推导**。最好的字段没人打字:一次输入每日输出是全类最高杠杆结构(距考试 N 天只花一个日期,回报四个月)。
- **Move 2 · 问一次,不问每天**。锚点日期一次设定;setup 输入近乎免费,每日输入最稀缺。
- **Move 3 · 每日输入压到一次点按**。一键不是表单;预填上次值;能用照片代替数字就用。**不为同一操作同时要单位、类目和备注**。
- **Move 4 · 改 hook**。前四步喂不饱,就换一句现有数据撑得住的句子——更小的真句子天天赢过更大的假句子;假句子第四天就露馅,还带走用户对整个页面的信任。

## 5. 两个机械测试 + 冷启动台词

**fortune-cookie 测试**:把 hook 按第 40 天、什么都没记的样子渲染出来。和第 1 天一样 → 不是 hook。机械判据:指着句中明天会不一样的那一块,指不出 → 重写。鼓励不是信息。

**stat-strip 测试**:结论条里每个分句问「看到这个数,他现在会做什么?」答案全是「知道了」→ 它没有祈使成分。系统域版本:纯总数(共 1,284 个客户)变化但没事做,要的是「3 个卡在报价超 10 天」这类可行动项;**两日测试**:day1/day2 并排写,陌生人分不出 → 变量太慢,撑不起每日 hook,降频为周级并明说。

**冷启动台词(day 1 / 2 / 7 写全,进 spec,成为 UI 空态)**:

| 日 | 现实 | 台词必须 |
| --- | --- | --- |
| 1 | 什么都没输入 | 只索要**一件**能解锁最多的输入,并说清它换来什么 |
| 2 | 有一条记录 | 把这条记录回显给它,附第一个哪怕很薄的规律 |
| 7 | 够出趋势 | 给出第一个真实计算出来的结论——产品自证的时刻 |

规则:day 1 禁六字段安装向导;禁 `--` / `0%` / 空图 / 骨架(像坏状态的状态和坏产品无法区分);禁为填满首屏编造演示数(用户会信,然后发现是假的,之后页上一切均可疑);day 7 写不出真实台词 = 深度低于你以为的。系统域更严:day 1 必须**命名一个带可见入口的具体动作**(拖一份 Excel / 建第一个 Agent),不是描述空;断连的集成要有独立于「空」的专属台词(「用量还没接上」和「本月没有花费」是两件事,给前者显示 ¥0 是谎言)。

## 6. 断签与陈旧数据

稳态包含间断,三种失败在此处决定而不是在代码里:

1. **陈旧数据充当今日**。今天什么都没记,hook 不得把昨天的数当当前渲染;标注「上次记录 · 3 天前」或切回重新入口台词。
2. **惩罚间断**。「已断签 3 天」+ 熄灭的火焰,会赶走正要回来的用户。间断已经发生,唯一的问题是他还回不回来——设计回归:「距上次 3 天,直接记今天的就行,不用补」。
3. **要求补录**。今天的输入永远不得以补历史为前置。

## 7. 与 state-empty-starter 的边界裁决

[`../vocabulary/states.md`](../vocabulary/states.md) 的 `state-empty-starter`(示例数据/模板预填 + 重置出口)与本门禁「禁假演示数」的仲裁:

- **首屏冷启动/hook 区**:真实优先。day 1 台词只索要一件事;任何演示数字不得出现在 hook、结论条、指标卡。
- **非首屏预览与教学场景**:允许 starter 示例数据,但必须显式标注为示例(产品内有「这是示例,重置为空态」出口),且不得流入任何跨会话复用的产物数据。
- 两者冲突时,以本门禁为准(hook 区禁假数),starter 只应用于内容区预填。
