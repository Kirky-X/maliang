# UX 心理学定律库 —— 设计决策的「为什么」层

> 规范层。[`ux-rules.md`](ux-rules.md) 回答「查什么」（可核对的 Do/Don't），本文回答「为什么」——每条定律给机制、一行 UI 可操作含义与适用边界，供设计推理与 critique 归因时引用，避免把规则当玄学。**不是名词表**：定律不替代规则，规则条目以 ux-rules.md 为准。来源：web-design-pascalorg §11 思想吸收（中文自研，非文本翻译），2026-09 吸收；定律条目的系统化学源见 Laws of UX（lawsofux.com，Jon Yablonski）。

## 一、交互与响应

| 定律 | 机制一句话 | UI 可操作含义 | 适用边界 / 回链 |
| --- | --- | --- | --- |
| **Fitts 定律** | 到达目标的时间由距离和目标大小决定 | 高频动作放大、放近；把相关操作聚到指针/拇指路径上 | 「边缘/角落有无限热区」仅桌面指针语境成立；移动端目标尺寸硬指标见 ux-rules `touch-target-44` / `web-target-size-24`，不能拿 Fitts 逻辑抵扣尺寸达标 |
| **Hick 定律** | 决策时间随选项数量与复杂度上升 | 每一步少给选项；复杂任务拆成小决策；给推荐默认项而非空白候选 | 不是「菜单 ≤7 项」的教条出处（那是误读）；底部导航 ≤5 的工程口径见 ux-rules `bottom-nav-limit`，两者来源不同 |
| **Jakob 定律** | 用户绝大部分时间在别的产品上，期待你的产品照同样的方式工作 | 交互模式遵平台惯例；要偏离惯例，先确认收益大于学习成本 | 惯例的具体化条目见 ux-rules `nav-state-active`、`back-behavior`；品牌创新放在视觉层，不放在交互层 |
| **Doherty 阈值** | 系统响应低于 400ms，用户生产率与容忍度显著上升 | 三级配合：点击即刻反馈（`tap-feedback-speed`）→ 短等待乐观更新 → 长等待骨架屏（`progressive-loading`） | 400ms 是感知目标而非接口 SLA；maliang 交互动效时长口径（≤400ms，见 [`dials.md`](dials.md)）与其同源 |
| **Tesler 定律**（复杂度守恒） | 每个系统都有删不掉的复杂度，问题只是谁承担 | 让系统吸收复杂度（默认值、自动填充、智能预设），界面保持简单 | 不是「能藏就藏」：被吸收的复杂度出错时必须可见可纠；表单自动复用见 ux-rules `redundant-entry` |
| **Postel 定律**（宽容输入，严格输出） | 对接受的输入宽容，对产出的输出严格 | 输入层宽容解析（电话号带空格/横线、日期多格式），输出层归一化 | 宽容 ≠ 放弃校验：解析失败仍要走 `inline-validation` 给具体错误；安全校验（金额/权限）不在宽容范围 |

## 二、记忆与注意

| 定律 | 机制一句话 | UI 可操作含义 | 适用边界 / 回链 |
| --- | --- | --- | --- |
| **Miller 定律**（7±2） | 工作记忆同时约持有 7±2 个组块 | 用来指导**分块**（chunking）：长表单分组、设置项归类、说明文分点 | 不是「单屏只准 7 个元素」的上限教条；分块后每组内条目数由扫描效率定，不硬凑数字 |
| **序列位置效应** | 列表首尾最易被记住，中段最易被遗忘 | 关键导航/操作放首尾（首项、末项、「更多」前一位），低频项放中段 | 对长列表（>10 项）收益递减——长列表靠搜索与分组，不靠排序赌记忆 |
| **Von Restorff 效应**（隔离效应） | 一组同质项中「异类」最容易被记住 | 每屏只让一个元素异质（主 CTA 换实色、关键指标换字重），其余保持同质 | 满屏都是高亮 = 没有高亮；异质手段见 [`ai-tells.md`](ai-tells.md) 反例（到处渐变/到处徽章） |
| **横幅盲视**（Banner Blindness / 选择性注意） | 用户会主动忽略「长得像广告」的东西 | 真实功能与重要信息禁止做成横幅/弹窗/闪烁样式；营销页的证言、信任要素避免横幅化 | 与 Persuade surface 的矛盾点：营销页可用视觉强调，但「功能入口伪装广告」永远禁止 |
| **蔡格尼克效应** | 未完成任务比已完成任务更难忘 | 多步流程给进度指示（第 2/4 步）、半填表单可恢复，利用完形压力推动完成 | 双刃剑：也意味着「被打断的任务」制造焦虑——退出前保存草稿（`back-behavior`），勿故意制造未完成感胁迫用户 |

## 三、体验与动机

| 定律 | 机制一句话 | UI 可操作含义 | 适用边界 / 回链 |
| --- | --- | --- | --- |
| **峰终定律**（Peak-End） | 人按「峰值时刻 + 结束时刻」评价整段体验，而非逐秒平均 | 资源向两处倾斜：流程高潮（结果呈现、对比揭晓）与结尾（完成页、成功动效、收尾文案） | 「结尾体验」含错误结尾：失败终态同样被记住，错误页/空态是峰终的一部分（ux-rules `empty-states`） |
| **目标梯度效应** | 越接近目标，动机越强、速度越快 | 进度条从头就「预填充」（已为你选好默认项）；多步流程展示剩余步数；会员/任务体系展示「差一点」 | 预填充必须是真实的、可改的；伪造进度（假装已完成 2 步）是 dark pattern |
| **帕累托原则**（80/20） | 约 80% 的使用集中在 20% 的功能上 | 优化前先找出关键 20%（高频路径），首屏、默认态、主流程优先打磨；长尾功能收进「更多」 | 20% 必须来自真实数据（[`analytics-events.md`](analytics-events.md) 埋点），不是拍脑袋；新页面无数据时按产品推理（[`product-reasoning.md`](product-reasoning.md)） |
| **美即好用效应**（Aesthetic-Usability） | 人把「好看」直接感知为「好用」，美观 buys 容忍度 | 视觉打磨本身就是可用性投资——redesign/去 AI 味（[`../commands/redesign.md`](../commands/redesign.md)）的价值依据 | 上限：美观只能买容忍度，不能抵偿硬伤；ux-rules ERROR 级条目（对比度/焦点/触控目标）不打折 |
| **选择过载** | 选项过多降低决策率与满意度，而非提升自由感 | 给默认推荐、可筛选（而非全量罗列）、把大决策拆成小步骤；定价页高亮「最受欢迎」 | 与 Hick 同根；区别在 Hick 管单次决策耗时，选择过载管决策后的放弃率 |

## 四、格式塔（Gestalt）知觉组织 6 原则

人眼自动把元素组织成组——布局系统（间距/对齐/容器）就是在操纵这些原则：

| 原则 | 一句话 | UI 可操作含义 |
| --- | --- | --- |
| **接近**（Proximity） | 靠得近的被看成一组 | 分组靠间距而不是靠框：组内间距 < 组间间距；表单 label 贴自己的输入框 |
| **相似**（Similarity） | 长得像的被看成相关 | 同类操作同色同形（所有次要按钮一个样式）；换样式 = 换含义 |
| **连续**（Continuity） | 排成线/曲线的被看成一体 | 步骤条、时间线用连续视觉线连接；对齐轴被打断即读作「另一个东西」 |
| **闭合**（Closure） | 心智自动补全不完整的形 | 图标/Logo 可做减法留白；进度环 87% 会被读成「快满了」 |
| **共同区域**（Common Region） | 同一边界内的被看成一组 | 卡片、面板、背景色块即分组手段；tab 页签与内容共区域 |
| **图底**（Figure-Ground） | 心智分离前景与背景 | 弹层必须有明确图底分离（遮罩 + 投影 + 海拔，见 [`../dimensions/elevation.md`](../dimensions/elevation.md)）；图底模糊 = 模态读不懂 |
