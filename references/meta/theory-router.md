# 理论模型路由 —— 判阶 + 段 × 理论包 + 复合规则

> 规范层(路由层)。回答「**现在处于哪个阶段、该用哪个理论模型做判断、什么条件用、怎么组合**」。三层数据流:本文(判阶/条件/组合) → [`design-theory-models.md`](design-theory-models.md)(全量 174 模型明细,按锚点查单条) → [`ux-laws.md`](ux-laws.md)(常用定律的机制与 UI 含义,重叠条目以它为 canonical)。阶段本体是 [`lifecycle.md`](lifecycle.md) 七段,本文不另造流程。理论是**推理/归因/说服层**:核对与门禁以 [`ux-rules.md`](ux-rules.md) 与 [`numbered-gates.md`](numbered-gates.md) 为准,理论判断不能抵扣规则(§3 决策链)。出处：模型清单取自 design-theory-models.md(

## 0. 使用协议(agent 三步)

1. **判阶**:进入子命令前跑 §1 判阶表(确定性查表,不是语言判断);
2. **选模型**:在判得段的理论包(§2)里按「触发条件」列匹配当前判断点,只查命中条目,不全读手册;
3. **组合**:一个判断点涉及多个维度时按 §3 复合规则组合,单次判断 ≤3 个模型。

「依据」列的读法:标 `ux-laws` 的查 [ux-laws.md](ux-laws.md)(canonical,本文不复述机制);标 `手册⟶<领域>`的在 [design-theory-models.md](design-theory-models.md) 对应领域章节查条目行(定义/何时用)。

## 1. 阶段自动识别(判阶表)

判阶是**确定性决策表**(规则7:不交给模型猜)。输入三类信号:**产物**(工作区文件存在性:DESIGN.md / ui-markdown\*.md / preview 产物 / 评分快照 / 框架代码)、**意图**(用户措辞,对齐 SKILL.md 子命令路由)、**当前位置**(本会话已进入的子命令)。已进入子命令时直接按 lifecycle「覆盖对照」映射段,不再判;未进入时自上而下首条命中即判:

| # | 条件(全部成立) | 判为 | 理论包 |
| --- | --- | --- | --- |
| J1 | 无 DESIGN.md | 段1 研究 · 段2 定义(design-md) | §2.1 / §2.2 |
| J2 | 有 DESIGN.md,意图=比较几版/方向未定 | 段2·3 发散(explore) | §2.2 / §2.3 |
| J3 | 有 DESIGN.md,目标页 ui-markdown 缺失或过期 | 段3 设计(draw-md) | §2.3 |
| J4 | 有 ui-markdown,意图=预览/看效果 | 段5 验证-预览(preview) | §2.5 |
| J5 | 有 ui-markdown,意图=转框架代码(ArkTS/Flutter/Element) | 段4 实现(draw-*) | §2.4 |
| J6 | 有 preview 产物或可访问页面,意图=评审/好不好用 | 段5 验证-深评(critique) | §2.5 |
| J7 | 已有产物,意图=改版/变好/去 AI 味 | 段7 迭代(redesign;Rebuild 回补 §2.1) | §2.7 |
| J8 | 有 ui-markdown,意图=页面关系/跳转/实现缺口 | 段7 迭代-关系(ui-graph) | §2.7 |

裁决规则:

1. **产物证据 > 意图措辞**——用户说"改版"但无 DESIGN.md,仍判 J1(SKILL.md 🔴 CHECKPOINT 禁止跳段);
2. 一次请求跨段(如"从零做个落地页")按段顺序**逐段**加载理论包,不全量加载;
3. 本表与 SKILL.md 子命令路由同构,判阶命中即路由对应子命令;两表冲突以 SKILL.md 为准。

## 2. 段 × 理论包

各段目标一句话引自 lifecycle;表列:模型 | 判断什么 | 触发条件 | 依据。

### 2.1 研究(段 1)—— 产品世界是什么?谁在用?

| 模型 | 判断什么 | 触发条件 | 依据 |
| --- | --- | --- | --- |
| 待办任务理论(JTBD) | 用户"雇用"产品完成什么任务 | 定义价值主张前;人口细分解释不了行为差异时 | 手册⟶用户研究与定性方法 |
| 用户画像(Persona) | 为谁设计、防"为自己设计" | design-md Phase 0a 用户三产出;研究发现分散需团队共享锚点 | 手册⟶用户研究与定性方法 |
| 同理心地图 | 用户说/想/做/感是什么 | 访谈记录杂乱,需要结构化综合时 | 手册⟶用户研究与定性方法 |

### 2.3 设计(段 3)—— 每页具体怎么搭?

| 模型 | 判断什么 | 触发条件 | 依据 |
| --- | --- | --- | --- |
| 格式塔 6 原则 | 分组/间距/容器是否传达正确关系 | 任何布局、分组、间距决策 | ux-laws |
| 视觉层级 + F/Z 型扫读 | 视线先落在哪、阅读流是否成立 | 首屏/落地页/长文页布局 | 手册⟶视觉与 UI 设计 |
| Fitts 定律 | 目标尺寸与距离定值 | 高频操作放大放近、按钮/热区定尺寸(硬下限见 touch-target-44,理论不抵扣) | ux-laws |
| Hick 定律 | 单步给多少选项 | 菜单/选项/步骤拆分犹豫时 | ux-laws |
| Miller 定律(7±2) | 分块粒度 | 长表单、设置项、说明文分点 | ux-laws |
| Jakob 定律 | 是否遵平台惯例 | 引入新交互模式前 | ux-laws |
| Tesler 定律 | 复杂度给用户还是给系统 | 默认值/自动填充/高级项收纳 | ux-laws |

### 2.4 实现(段 4)—— 代码怎么落地?

| 模型 | 判断什么 | 触发条件 | 依据 |
| --- | --- | --- | --- |
| Jakob 定律 | 组件行为是否符合该框架惯例 | draw-* 组件映射犹豫时 | ux-laws |

| 模型 | 判断什么 | 触发条件 | 依据 |
| --- | --- | --- | --- |

| GOMS / KLM | 无用户时比较方案操作效率 | 两个交互方案争持不下、无法召集用户 | 手册⟶交互定律与启发式 |

| HEART 框架 | 体验指标体系 | 产品级度量建设(埋点对齐 analytics-events) | 手册⟶数据驱动与定量验证 |
| 5 秒测试 | 首屏传达了什么 | 首屏/落地页传达检验 | 手册⟶数据驱动与定量验证 |
| 首次点击测试 | 第一击是否指向正确路径 | 导航与信息气味检验 | 手册⟶数据驱动与定量验证 |
| 定律归因(ux-laws 全库) | 评分低项的"为什么" | 评分定位问题后归因(诊断链第一环) | ux-laws |
| 眼动追踪 | 实际注意分布 vs 扫读预期 | 有实测条件时(不可凭空推定) | 手册⟶数据驱动与定量验证 |

### 2.6 交付(段 6)—— 怎么交出去?

理论包**为空**:交付段用 preview-checklist 与编号门禁,不用理论模型。唯一例外:峰终定律提醒交付说明的首尾体验(依据 ux-laws)——但这属于呈现纪律,不构成判断依赖。

### 2.7 迭代(段 7)—— 怎么持续变好不漂移?

| 模型 | 判断什么 | 触发条件 | 依据 |
| --- | --- | --- | --- |
| 峰终定律 | 改哪收益最大 | 改版优先级论证(资源向峰值与结尾倾斜) | ux-laws |
| 目标梯度效应 | 进度感如何推进 | 任务体系、多步转化、进度预填(须真实) | ux-laws |
| 福格行为模型(B=MAP) | 流失缺的是动机/能力/提示哪个 | 转化率或功能使用率不佳的归因 | 手册⟶认知心理与行为设计 |
| Hooked 上瘾模型 | 习惯回路是否成立 | 回流型产品迭代(**必过伦理闸**) | 手册⟶认知心理与行为设计 |
| 暗黑模式 / 价值敏感设计 | 说服手法是否越界 | 任何增长/说服设计审查(伦理闸本体) | 手册⟶设计伦理与暗黑模式 |
| A/B 测试 | 改版效果判定 | redesign 基线比对(对齐 analytics-events) | 手册⟶数据驱动与定量验证 |
| 双钻回炉 | 是否需要重走发现 | redesign Rebuild 模式入口判定 | 手册⟶设计流程与方法论 |
| 美即好用效应 | 视觉投资回报论证 | Deslop/Refresh 模式价值依据 | ux-laws |

## 3. 复合规则(多模型组合)

组合前提:每个模型必须贡献**不同维度**(诊断 / 排序 / 校验 / 伦理),同维度堆砌=冗余;单次判断 ≤3 个模型,超过说明问题该拆。

| 组合名 | 成员(按序) | 适用情境 | 分工 |
| --- | --- | --- | --- |
| 诊断链 | Nielsen 10 → ux-laws 定律 → ux-rules slug | critique/preview 发现问题并解释 | 评分定位问题 → 定律归因 → 规则定修复 |
| 决策链 | 理论模型 → 规则/门禁 | 用理论定值后必走 | 理论给方向,规则给底线(如 Fitts 建议放大目标,touch-target-44 仍是硬下限) |
| 降载链 | 认知负荷 → Hick → Miller →(仍不够)渐进式披露 | 信息密度大/选项多/表单长 | 先减总量 → 再拆单步 → 再组分块 → 最后才分层披露 |
| 转化链 | 福格 B=MAP → Von Restorff → 峰终 | Persuade 页/首屏转化 | 诊断缺 M/A/P → 唯一异质 CTA → 峰值与结尾投资 |
| 旅程链 | 旅程地图 → 关键时刻(MOT) → 峰终 → 目标梯度 | 多步流程/留存优化 | 定位触点 → 找关键时刻 → 投资峰终 → 真实进度推进 |
| 伦理闸 | 转化链/旅程链/Hooked 之后强制追加暗黑模式检查 | 任何说服类组合的出口 | 未过闸的说服设计不得进入 draw-md(判据见手册⟶设计伦理与暗黑模式) |

## 4. 边界与分工

- 阶段本体、载体与出口检查点以 [`lifecycle.md`](lifecycle.md) 为准,本文只挂理论包;
- 定律的机制/UI 含义/适用边界以 [`ux-laws.md`](ux-laws.md) 为 canonical,本文只路由不复述;
- 条目定义与出处以 [`design-theory-models.md`](design-theory-models.md) 为详尽层,按锚点查单条;
- 可核对规则与门禁以 [`ux-rules.md`](ux-rules.md) / [`numbered-gates.md`](numbered-gates.md) 为准,理论判断不能抵扣;
- 模型清单 2026-10-25 随手册登记;手册修订(增删条目)时同步本文路由表,两处模型名保持一致。
