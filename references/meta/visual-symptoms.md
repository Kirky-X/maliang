# 感知症状诊断表 —— 「说不出的不对劲」的机械定位

> 规范层。对现成 UI 的感知症状投诉（「太挤 / 像数据库导出 / 过度分框 / 说不出的廉价感」）几乎总是模糊的；每个模糊症状映射到少数几个**具体、机械**的修复，不需要品味投票。本表回答「哪坏了、从哪修」；改动清单的输出顺序仍按 [`../commands/critique.md`](../commands/critique.md) / [`../commands/redesign.md`](../commands/redesign.md) 的「结构 → 视觉 → 交互动效 → polish」依赖序分组——**症状表与依赖序正交互补**：症状表定位病灶，依赖序决定先输出哪组；症状表不做顺序裁决。
>
> **自上而下扫，头部条目覆盖多数损害**：页面级病灶（层级 / 间距 / 分框）放最前，多数翻车在这里；局部症状在后。来源：refactoring-ui-skill 仓的 diagnose.md(#9)，2026-10 吸收；分组、危害排序与中文表述自研。

## 入口与用法

- [`../commands/critique.md`](../commands/critique.md) 感知症状投诉：先对本表定位病灶，再走全量评审——症状表回答「哪坏了」，评审回答「多严重、先修啥」。
- [`../commands/redesign.md`](../commands/redesign.md) 第 2 节审计前的症状速查：命中项直接进改动清单，不为凑全量重走已定位的病灶。
- 修复手法涉及层级方法论的（label 折进 value / 重量与对比互偿 / baseline 对齐），细则见 [`ux-rules.md`](ux-rules.md) 对应 slug（`label-fold-into-value` / `weight-contrast-balance` / `baseline-align-mixed`）；边框代空间、居中滥用等签名判定见 [`ai-tells.md`](ai-tells.md)。
- 用法纪律：**逐行对照真实渲染判断**，不凭截图印象跳读；一条症状命中多个病灶时按表中行序取最前（危害序即修复优先序）；修复后复渲染对比，不靠记忆判断「好没好」。

## 一、页面级症状（危害最高，先扫这里）

| 症状 | 真正的病灶 | 修复 |
| --- | --- | --- |
| 嘈杂混乱、「内容墙」、没有视线焦点 | 无层级——所有元素等权重 | 刻意弱化次级与三级内容（降透明度 / 去色 / 缩小），而不是继续放大主角 |
| 某个元素怎么都突出不了 | 它的邻居在跟它抢 | 软化竞争者：非当前导航项降透明度、去掉侧栏背景让内容前浮 |
| 拥挤、局促、透不过气 | 空间是「加到刚好不难看为止」加出来的 | 先给远超需要的留白再逐档削减；密集 UI（dashboard）合法，但必须是显式决策不是默认 |
| 分组含糊——哪个标签配哪个字段？哪个标题管哪段？ | 组内与组间间距相等 | 组**外**间距必须大于组**内**间距；同病的变体：列表 gap 须大于行高、横向行同理 |
| 繁忙、框格化、过度分格 | 边框太多 | 换成阴影 / 两种微差背景 / 纯间距；边框与底色变化同时存在时删边框；**识别控件**的边框（输入框描边、checkbox 边）保留且需 3:1 |
| 版面在大屏上摊得很薄 | 因为空间在那儿就填满 | 只用内容需要的宽度；或分栏而不是拉伸 |
| 侧栏大屏太宽、小屏被截断 | 侧栏用了栅格百分比宽 | 侧栏定宽，主内容 flex |
| 移动端标题巨大 | `em` 尺寸从桌面端带过来 | 按断点独立定字号；大的元素收缩得比小元素快 |
| 页面标题感觉过大、压场 | `h1` 按 `h1` 的默认样式排 | 区块标题通常是 label，16px 足够；必要时视觉隐藏 |

## 二、文本与数据（次高）

| 症状 | 真正的病灶 | 修复 |
| --- | --- | --- |
| 数据读起来像数据库导出（`Name:` `Email:` `Phone:`） | 朴素的 label/value 对 | 格式或上下文已说明的 label 直接删；label 折进 value（「3 bedrooms」不是「Bedrooms: 3」）；否则让 label 明显次级（见 [`ux-rules.md`](ux-rules.md) `label-fold-into-value`） |
| 彩色面板上的文字发灰、发闷、像禁用 | 灰字或半透明白字压在色底上 | 在背景色相内手选一个调过饱和度 / 明度的前景色（翻转对比与色相旋转两个逃生舱见 [`../dimensions/color.md`](../dimensions/color.md)） |
| 大标题压在照片上，某些尺寸下读不清 | 图太「吵」，不是字的问题 | 半透明遮罩；或降图对比并用提亮补偿；或去饱和后叠品牌色正片叠底；或大模糊零偏移 text-shadow 当光晕 |
| 主内容过大**且**次内容过小 | 字号独自扛层级 | 强调移到字重（600/700）与颜色上，字号向阶梯中部收 |
| 同一行混排字号看起来没对齐 | 垂直居中 | `align-items: baseline`（见 [`ux-rules.md`](ux-rules.md) `baseline-align-mixed`） |
| 全大写标签难读 | 默认字距按句子场景调的 | 加 ≈0.05em letter-spacing |
| 两端对齐的段落出现「河流」空白 | 没有连字 | `hyphens: auto`，或干脆不 justify |
| 长段落居中难读 | 居中用过了 2-3 行 | 左对齐；或把文案改短到居中成立 |
| 表格数字列难比较 | 数字左对齐 | 数字右对齐 |
| 每个链接都带色，满屏强调 | 散文链接样式被用在链接密集的界面 | 用字重或更深的颜色做强调；纯辅助链接只在 hover 出样式 |

## 三、图标、图片与资产

| 症状 | 真正的病灶 | 修复 |
| --- | --- | --- |
| 图标压过旁边的文字 | 实心图标覆盖面积大 | 降图标对比度（换更柔的颜色），不动尺寸（见 [`ux-rules.md`](ux-rules.md) `weight-contrast-balance`） |
| 1px 边框要么看不见要么刺眼 | 想用颜色解决重量问题 | 保住柔色，加粗到 2px |
| 大图标看着又粗又糙 | 16-24px 的图标被硬放大 | 不放大：按原始尺寸放进彩色圆 / 方容器里 |
| 截图缩小后是一团糊 | 全尺寸截图硬缩 | 截小视口（平板）/ 裁一个区域 / 画简化示意 |
| logo 缩成 favicon 就成糊 | 细节图稿硬缩 | 按目标尺寸重画简化版 |
| 头像 / 缩略图丢了形状 | 图片背景与 UI 背景同色 | 内阴影 `inset 0 0 0 1px hsla(0,0%,0%,.1)`，不用边框——边框会跟图片颜色打架 |
| 用户上传的图毁了栅格 | 按原始宽高比展示 | 固定容器 + `background-size: cover` 裁掉溢出 |
| 重叠的图片互相打架 | 图与图之间没有分隔 | 加与页面背景同色的边框——「隐形边框」保证间隙 |

## 四、气质类（「没毛病但也没对的地方」）

| 症状 | 真正的病灶 | 修复 |
| --- | --- | --- |
| 平、素、「没毛病但也没对的地方」 | 全页没有一处视觉重音 | 色彩重音：卡片顶边 / 标题下方 / 告警侧边的 accent 线、换某一节的背景色、≤30° 双色相渐变、沿一条边走的低对比纹理——不需要铺满整个背景 |
| 像没完成的原型 | 满屏浏览器默认样式 | 列表符换图标；品牌色自绘 checkbox / radio；引语升格为视觉元素；链接给专属样式 |
| 新用户看到空白屏 | 空状态是事后想法 | 插画 + 明确 headline + 强调 CTA；内容出现前隐藏空转的 tab / 筛选 / 搜索 |
| 组件看着普通 | 用了组件的默认心智模型 | 破框：多列带图标与描述的下拉、合并列 + 内嵌图的表格、可选卡式的 radio 组 |
| 元素像贴纸一样浮在页面上 | 一切都待在自己的矩形里 | 层叠：负 margin 让卡片骑在两种背景上，或伸出父容器边缘 |
| 图表色盲用户读不了 | 数据序列靠色相区分 | 改用同一色的明度阶梯区分；色码指标补图标 / 箭头 |
