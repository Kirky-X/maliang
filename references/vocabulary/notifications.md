# 通知设计模式命名词汇

> 术语库。通知是"把值得用户知道的事送到用户面前"的一组模式,本表标准化其分级命名与投放纪律。与页面状态(states.md)、浮层链路(popups.md)互补:popups 管 banner 载体与浮层交互,本篇管分级、授权、文案与角标策略。

## 命名表

| 模式名 | 构成要素(形态/打断强度) | 适用场景 |
| --- | --- | --- |
| `notif-passive` | 被动展示:角标计数、收件箱红点、摘要区静默追加,零打断 | 低价值可延迟信息(内容更新、静态资讯);用户回来自见,不应打扰 |
| `notif-banner` | 顶部横幅/Toast,自动消失,留一条行动入口 | 默认级:中等价值、即时但不紧急(评论回复、任务完成);载体与出入场动效见 [`popups.md`](popups.md) banner-notification |
| `notif-urgent` | 置顶展示 + 穿透专注/勿扰模式 + 持续驻留直到处理 | 时间敏感级:事件正在发生或一小时内发生(快递到门口、直播开始、会议 5 分钟后);准入极严,见使用规则 |
| `notif-critical` | 全屏警报 + 强提示音,无视静音设定 | 危及安全/健康/财产(安防报警、医疗监控);Web 产品几乎不用,误用即灾难 |
| `notif-digest` | 摘要合批:固定节奏(每日/每周)汇总低价值高频事件 | 降噪:把 N 条 `notif-banner` 合成 1 条精选摘要,用户可配置节奏 |
| `notif-badge` | 角标数字/圆点,常驻图标或标签上 | 只表达未读计数,不表达天气/股价/比分等其它语义 |

## 使用规则

- **紧迫度诚信**:如实定级。禁止用高紧迫级送低价值或营销信息——信任一旦破坏,用户直接关闭全部通知
- **urgent 准入判定**:事件正在发生或一小时内发生才可标时间敏感;营销/推广通知必须显式 opt-in 后才可发,且永远不得使用 urgent/critical 级
- **错误不走通知**:错误信息用 alert/页内提示呈现(见 [`popups.md`](popups.md)),通知不承载错误;用户正停留在页面内时也不发通知——改为角标递增或行内插入新数据
- **不重复轰炸**:同一事件只发一条,用户未响应也不补发
- **发信息,不发指令**:通知内容是"发生了什么",不是"请你去做 X"——指令在用户点开后由页面承接
- **标题与正文**:标题短、无尾标点;Web 场景标题写发信主体(人名/系统模块);预览降级文案(通知被隐藏时的替代文案)要通用且不泄露内容("新评论"而非评论摘要)
- **行动入口 ≤ 4 个**:通知上操作按钮最多 4 个,全部非破坏性;不放"打开应用"按钮——点击通知本身就是打开;破坏性操作必须先回到应用内确认
- **角标纪律**:角标只表未读数;清零即同步移除对应通知;角标不是唯一通道(用户可能关掉它);禁止自制仿系统角标的装饰组件
- **后台任务完成通知分级**:用户发起的下载/处理/导出类任务切走后必须继续完成;重要或时间敏感任务完成可发 `notif-banner` 召回,例行次要任务完成不发,用户回来自己看
- **偏好管理入口必设**:应用内提供通知偏好设置(分级开关/节奏/退订),用户可随时改授权;与 [`settings.md`](settings.md) 的设置分流互链
- **与 states.md 分工**:通知是"推送侧"模式;页面内的 Loading/Empty/Error 状态呈现见 [`states.md`](states.md)

## 在 draw-md 中的写法

```markdown
## Notifications
- levels: [notif-passive, notif-banner, notif-urgent]
- digest: { pattern: notif-digest, cadence: daily }
- badge: { pattern: notif-badge, semantics: unread-count }
- consent: opt-in, management-entry: /settings/notifications
- rules: [marketing-never-urgent, no-duplicate-per-event, actions-max-4]
```
