# explore 子命令 —— 多方案发散-比较-收敛

> 本文件是 `explore` 子命令的完整流程,由顶层 [`SKILL.md`](../../SKILL.md) 路由进入。
> 定位:回答「**方向选哪个**」——方向未定时实体化几套**真不同**的完整页面方案,用 preview 体系渲染成可实时切换的比较器,用户选定胜者后收敛回主链路(design-md → draw-md → preview → draw-*)。
> 来源：prototype skill(发散-比较-收敛工作流、比较器 harness 规范、riff/keep 语义)，2026-09 吸收,全稿中文自研重写;发散层级取规格层方案——每方向实体化一份完整页面规格再渲染比较,复用 maliang 既有链路,不引入独立原型栈。
> 方向卡字段与程度、差异检验、拆标杆与骨架配额、对比页 manifest、选择回传:来源:oil-ui 仓与 qiaomu-design 仓,2026-10 吸收,按 maliang 口径重写(16 栏字段表、8 条差异检验、无本地回传服务时走 file:// 降级)。

## 何时进入 / 何时绕行

与相邻能力划界,防第二模式:

| 相邻能力 | 它管什么 | 本子命令的边界 |
| --- | --- | --- |
| design-md Phase 4 变体引擎([`design-md-advanced.md`](./design-md-advanced.md)) | 同一份 DESIGN.md 的 **token 层**派生(暗色 / 季节 / A-B / 子品牌) | 方案级发散(布局 / 密度 / 人格 / 交互模型不同)才走本子命令 |
| redesign 四模式([`redesign.md`](./redesign.md)) | 对**已存在 UI** 的改版 | 产出前的方向探索走本子命令,不碰既有实现 |
| component([`component.md`](./component.md)) | 单组件轻流程 | 整页 / 整区块的方向选择才走本子命令 |
| dials DESIGN_VARIANCE([`../meta/dials.md`](../meta/dials.md)) | **单方案内**视觉变化丰富度档位 | 方案**数量与方向差**由本子命令「真不同」判据管,两套轴不混用 |
| draw-md 步骤 2.6 线框构思([`draw-md.md`](./draw-md.md)) | 布局未定时的内部思考(不渲染) | 需要渲染成真预览供人选时升级到本子命令 |

**触发**:新页面类型没有既定方向、多种信息架构都说得通、用户明确想「先看几版再定」。
**不触发**:方向已定(直接 draw-md)、改版现有页(redesign)、单个组件(component)。

## 轻量档 · 文生图方向板(可选)

用户只要**快速看视觉方向**(风格/氛围/布局意象),尚不需要可交互比较器与可发布规格时,可用本档替代第 3-4 步的重链路:把各方向词交给 wudaozi t2i **分节出图**——每个方向按节出横图,每节一张、逐张标注 `Section X of N`,跨帧锁同一 brand world;出图纪律(张数、design bible、禁裁剪旧图、生成前自查)照 [`wudaozi`](../../../wudaozi/references/multi-image-discipline.md) 的 multi-image-discipline 执行,构图锚点按内容选,不吃「左文右图」的条件反射默认。

边界:方向板是**意象参考,不是规格**——不含 token、不可发布、不满足 draw-md 硬约束;用户选定方向后必须回到主流程第 3 步实体化成 draw-md 规格(值引用 token),方向板不得经 keep 直接晋级生产面。来源:imagegen-frontend-web(license 未考,思想内化),2026-10 吸收。

## 流程

### 1. 定界与侦察

一次探索聚焦**一个页面 / 一个区块**;范围横跨多页时,挑杠杆最大的一个,其余列为后续轮次。动手前摸清各方向要站住的地面:DESIGN.md token(色彩 / 字体 / 间距 / 圆角 / 时长)、三个 dial 档位(DESIGN_VARIANCE / MOTION_INTENSITY / VISUAL_DENSITY)、页面模式(见 [`../meta/surface-modes.md`](../meta/surface-modes.md))、渲染语境(端型 / 容器 / 邻接区块)。**数据型界面(首屏含数值 / 进度 / 结论条)加一步:按 [`../meta/workbench-structures.md`](../meta/workbench-structures.md) 判主副结构**——主结构拥有 hook 与首屏主导显示,发散方向不得违反它(`pipeline` 主结构的首屏是看板不是表格);首屏数据条款按 [`../meta/data-floor.md`](../meta/data-floor.md) §2 过绑定表,过不了的方向不进比较器。

> 🔴 **CHECKPOINT · 前置输入**:无 DESIGN.md 时先引导用户走 design-md;用户坚持探索的,按 SKILL.md「失败模式与 fallback」第一行同款处理——用克制默认外观 + 临时 token 占位,并显式标注「待 DESIGN.md 建立后回填」。方向清单未经用户确认不进入实体化。无人值守(用户说「你定/直接做」或不在场)时不等确认:按 SKILL.md「无人值守与 CHECKPOINT 降级」取默认值,用克制默认外观 + 临时 token 占位并标注「待回填」,直接推进。

### 2. 选方向(发散)

默认 **3 个**方向;用户要求或设计空间确实宽时**至多 5 个**——超过 5 个稀释比较。每个方向:

- **方向词命名**(如「编辑排版」「工作台高密度」「卡片流」),禁「方案 A/B/C」;
- **声明分歧轴**(布局 / 密度 / 人格 / 交互模型),一句话说得清这个方向在哪根轴上与其他方向不同;
- **可独立发布**:每个方向都是一份整页可交付的完整方案,不是同一方案换强调色的换肤;
- **craft bar 不降**:发散不豁免质量——每份规格单独满足 draw-md 全部硬约束(token 引用 / aria / 触控 ≥44px / 动效 ≤400ms),执行差的方案只会输在执行上,测不出它代表的方向。

**先选生成引擎,再落方向卡**——每个方向从一个**具体的引擎**出发,不从形容词出发,不同方向用不同引擎;引擎的内容来自这个产品的证据(受众、内容、使用场合、品牌已有资产)。引擎六类:

- **材质 × 环境**:一种材质放在一个具体的环境里,由它推出光照、深度、边缘处理与动效阻尼;
- **一个具体场景**:有时间、地点、光线的场景,由场景的光线 / 声音 / 材料 / 节奏推出质感与动效速度(适合情绪型工具);
- **角色原型**:给产品一个具体性格,让性格决定字体和动作;
- **设计运动或文化语法**:选一个与题材、受众或地域有真实联系的运动或视觉传统,借它的语法,不贴它的图案;
- **其他领域的整套表现形式**:只借最有辨识度的一两个手法,不把那个媒介的部件一件件搬来(道具堆砌);
- **有意打破常规**:激进的非对称、不和谐的配色与字体、让人不安的留白,但整体仍好看、功能完整。

### 2.1 方向卡(16 栏,每栏写到规定程度)

每个方向写一张方向卡,每栏填具体选择,不填形容词。**出首屏的那一轮只填 7 栏**(北极星 / 生成引擎 / 首屏骨架 / 字体 / 色彩 / 主视觉 / 图标与控件语法);其余 9 栏在方向选定后、做完整页面之前补齐。派生版式时,每个版式变体只重写**首屏骨架 / 页面结构 / 主视觉**三栏。

| 字段 | 要写到的什么程度 |
| --- | --- |
| 北极星 | 一句能指导取舍的体验意图:用起来像在什么地方、做什么事 |
| 调性 | 五个刻度(能量 安静↔喧闹 / 完成度 粗粝↔精致 / 密度 疏↔密 / 分量 轻↔重 / 严肃度 活泼↔庄重)的取值及依据;依据来自受众、内容和使用场合——证据指向喧闹粗粝却交付米色卡片与柔和阴影,是最常见的失败 |
| 标杆与取舍 | 品类是什么,拆的是哪一家,对着哪几张真实画面拆(写存放路径);沿用了哪几条、换掉了哪几条,各自为什么;拿不到画面时见「拆标杆」末条 |
| 生成引擎 | 用了上一节六类中的哪一种,具体是什么,来自这个产品的什么证据 |
| 首屏骨架 | 先写用户来首屏**看什么、做什么**;说服型页面写从骨架表选的哪一种(骨架见 [`../vocabulary/hero.md`](../vocabulary/hero.md)「首屏骨架表」),附 **3–5 个方框的首屏线框:每块是什么、占多大面积、阅读从哪里开始**;内容 / 工作区页写首屏能看到几个对象、页头占几行 |
| 页面结构 | 首屏以下怎么组织,例如单列沉浸滚动,或导航、内容、详情三栏 |
| 各区块的形式 | 首屏以下每个主要区块(产品实样、功能、价格、隐私、结尾等)在这个方向里长成什么东西;形式从生成引擎推出,不是同一个模块换颜色 |
| 字体 | 具体字族、字重和尺度关系:展示、正文、数字各用什么,相差多大;显示级口径见 [`../meta/ai-tells.md`](../meta/ai-tells.md) 第 11 节与 [`../dimensions/font.md`](../dimensions/font.md) |
| 色彩 | 按下方「定色彩」四步写:至少三层十六进制色值(底色 / 主强调 / 派生的选中底与描边)及用途,再加一句它来自这个产品的什么 |
| 主视觉 | 哪张图或哪个图形承担情绪与识别,来自复用、生成还是排版本身 |
| 图标 | 用哪一套、什么描边粗细和端点,或者不用图标、改用字符和编号 |
| 控件语法 | 按钮、输入、选中、标签、状态和动效共用的一套形状和手感,一句话写清,例如圆角多大、描边多粗、按下时怎样变化 |
| 动效 | 手感用「一个拟声词 + 一个实物的动作」写(实物从产品领域里找);三处基本动效各怎么动、怎样彼此呼应 |
| 结构性突破 | 改变首屏结构的那一处偏离常规,以及它怎样放大北极星;手写批注、质感按钮、划线这类局部细节不算 |
| 记忆点 | 集中发力的一两处:什么时刻或位置,用什么材质、动作或画法 |
| 放弃什么 | 这个方向主动不要的常见做法 |

**定色彩四步**(色彩栏的展开):①先写两行共用——不看这个产品、只凭品类会顺手给出的配色(底色 + 强调色),以及拆过的标杆各占了哪个色相和明暗;②每个方向从这两者之外选一个色相家族和明暗(或明确的黑白),用一句写它来自这个产品的什么——颜色不直接取生成引擎里材质或场景的固有色,隐喻一落到材质,各产品最后会落在同一组颜色上;③写出至少三层:底色、主强调,以及由它们派生的选中底、描边和禁用态;④自检——去掉所有发光和模糊后配色是否还成立,它是从这个产品推出来的,还是一组放在哪个产品上都不出错的安全色;是后者,回到第②步。黑白灰加一种强调色、甚至完全不用彩色,也是完整的色彩身份。**几个方向之间不按明暗分**:头号失败是「一个亮、一个暗、一个暖」——每个方向要有自己的色相家族或材质感,明暗只是结果。

**模糊词必须翻译**(方向卡里禁写「高级 / 精致 / 克制 / 史诗 / 文学感 / 简洁」这类词,写出来就要翻译成可观察的决定,翻译不出的从理由里删掉):

| 模糊词 | 翻译成什么 |
| --- | --- |
| 高级 | 先说清是哪一种高级,再决定字体的对比、分隔的方式、间距的尺度和色相的数量 |
| 精致 | 公差:字距怎么调、对齐到几像素网格、阴影最多几级、色相最多几种 |
| 克制 | 饱和度预算(强调色不超过画面 10%)、动效幅度上限、色相数量上限 |
| 史诗 | 尺度:展示字多大、主图占多少面积、明暗对比多强 |
| 文学感 | 字族的性格、行长、行高和配色各取什么值 |
| 简洁 | 密度档位,以及删掉什么、为什么删——简洁是结果,不是指令 |

### 2.2 拆标杆(三步,每步都写下来)

1. **说出品类和标杆**:这是什么品类的产品,这个品类里风格最鲜明的两三家是谁——选风格最鲜明的,不一定是最有名的。
2. **拿到真实画面,再拆其中一家**:用宿主的浏览器或搜索,取这两三家标杆的首屏和一个关键控件的真实画面,存进任务目录,对着图拆,不凭记忆写——记忆里的产品常常是它几年前的样子。某一家的页面打不开或是 404,换一个地址再试一次,还不行就换一家;拿到两家真实画面就够,打不开的页面不算参考。拆成 6–10 条看得见的要素,每条写两件事:它是什么样、它为什么这样做;拆到能照着做的程度(形状、尺寸关系、状态怎样变化、服务什么使用场合)——只拆出「干净、留白、一种强调色」,说明没拆到位,换一家重拆。
3. **决定留什么、换什么**:拿本产品的受众、内容和使用场合逐条对照,理由同样成立的留下,理由不成立的换掉,换掉的部分由生成引擎给出替代。结果写进方向卡的「标杆与取舍」。

拆的时候分清三样东西:**基线**(用户已经期待的结构,沿用它,用户不用重新学)、**套路**(品类人人都在用的默认版式,一轮方向里至少一个要打破它)、**撞脸**(字体、配色、主视觉和图标都和某个标杆一样,只换了名字——任何方向都不允许)。确实拿不到画面时,在方向卡「标杆与取舍」开头写明「**未看图,凭记忆**」,并把**字体、色彩、主视觉三栏标为待验证**——这三栏最容易凭记忆写成模型默认。

### 2.3 首屏骨架先于文案

写文案之前先定骨架,**文案去适应骨架**,不让骨架去适应「标题 + 说明 + 按钮」的组合。先回答一个问题:用户来首屏是看什么、做什么?

- **来说服、传递理念的页面**(落地页、品牌页、产品发布页、展览页):从 [`../vocabulary/hero.md`](../vocabulary/hero.md)「首屏骨架表」的 8 种骨架里选,跳出左右分栏这个默认;骨架定好后抽 3–5 个方框画首屏线框。
- **来看内容、挑东西或处理对象的页面**(画廊、商店、信息流、文档、作品集、工具和后台):首屏就是第一排内容本身或工作区。导航、标题和筛选合起来不超过一两行,第一排内容要完整出现在首屏;不放首屏口号,也不放解释这个页面是干什么的段落。按用户最常做的动作安排内容。
- **两种都有时**(例如商店首页顶上有活动横幅):以用户最常来做的事为准,横幅可以留,但不能把第一排内容推出首屏。

### 2.4 差异检验(8 条,逐条可判)

方向卡写完、做首屏之前,逐条检验。基于选定方向派生版式、或用户已给品牌规范时,字体和配色是共用的,涉及字体和色彩的检验项不适用,骨架、主视觉和页面结构仍要各不相同。

| # | 检验 | 判定与处置 |
| --- | --- | --- |
| 1 | 比线框,不比描述 | 把各方向的首屏线框并排放在一起比——描述可以各不相同,线框却可能都是「左边大标题,右边一块」;线框相似就是同一骨架,重选骨架 |
| 2 | 四项至多一项相同 | 首屏骨架、字体、色彩、主视觉四项里,任意两个方向至多一项相同;否则就是同一方向的变体,换一个生成引擎重写其中一个 |
| 3 | 不按明暗分方向 | 每个方向有自己的色相家族或黑白;「一个亮、一个暗、一个暖」不算真不同 |
| 4 | 结构也要不同 | 填了「页面结构」的方向,页面组织不能完全相同、只换颜色和质感;候选只需共享核心内容和主要任务 |
| 5 | 至少一个走到极端 | 在证据允许的调性范围内,至少一个方向在构图、色彩和主视觉上都取明确的选择、不做折中;折中的方向最多一个 |
| 6 | 至少一个打破品类惯性 | 在同一调性内,至少一个方向不用这个品类的默认版式。常见套路:后台＝左侧栏 + 顶栏 + 卡片网格;电商＝大横幅 + 商品网格 + 页脚;社交＝底部标签栏 + 信息流 + 悬浮按钮;聊天＝左侧联系人 + 右侧消息;AI 与开发者工具＝黑底 + 紫蓝发光弥散圆晕 + 浮空粒子 + 千篇一律的胶囊按钮;落地页＝主视觉 + 特性 + 用户评价 + 最后一个行动按钮。打破套路不等于抛弃基线 |
| 7 | 不撞脸 | 把每个方向和它拆过的标杆并排看,撞脸就重做;沿用基线不算撞脸 |
| 8 | 盲看 | 遮住名字和说明只看画面,仍能说出每个方向带给人的不同感受 |

**块面复查**:首屏做出来后,在对比页并排看首屏,**缩到 480px 宽(或眯起眼睛)只看明暗块面**——块面分布如果相似(都是左边一大块、右边一小块),即使字体和颜色都不同,也回到骨架表重做,**不靠换装饰补救**。

**完成判据**:每个方向有名字 + 已声明分歧轴,且**任意两个方向不共享同一轴位**;任意两个方向在**明度轴或时代气质轴**上必须取值不同(两轴口径见 [`../templates/variation-engine.md`](../templates/variation-engine.md)「跨方向七轴」)。只差强调色或文案 = 同一方向,必须替换为真替代(换布局 / 换交互模型 / 换动效叙事);构建中途发现两个方向收敛了,砍掉一个并明说。

### 3. 规格层实体化

每个方向实体化**一份完整页面规格**,draw-md 格式(frontmatter + 方向契约块 + 布局章节 + 组件参数表,值引用产物层 `token.md`),落探索面目录(见「探索面与生产面隔离」)。方向间允许各自的原型 `organisms/`,但只存在于探索面内部。

> 🔴 **CHECKPOINT · 实体化完成**:每份规格单独过 draw-md 自检(验证点 5.2 token 引用 / aria / 触控 / 动效时长),全绿才进渲染;任何一份不合格就修它,不带病进比较器。无人值守时按 SKILL.md「无人值守与 CHECKPOINT 降级」取默认值,不因无人确认而停在原地。

### 4. 渲染与比较器

用 preview 体系渲染每份规格(自包含 HTML,file:// 可开;无本地回传服务时走 file:// 降级路径,不阻塞本轮),再产出一个**比较器页**把 N 个方向挂到同一条切换条下,行为契约见「比较器 harness 规范」。

**先写 manifest,再生成对比页**(生成器 [`../../scripts/build-explorer.py`](../../scripts/build-explorer.py),输入 manifest 路径,输出生成在 manifest 旁边;任务里不临时另写组装工具):

```json
{
  "schemaVersion": 1,
  "project": "<项目名>",
  "brief": "<所有方向共同表达的内容与主要任务>",
  "round": "<轮次，例如 01>",
  "candidates": [
    {
      "id": "<小写唯一标识>",
      "name": "<方向名>",
      "concept": "<北极星：一句能指导取舍的体验意图>",
      "typography": "<实际使用的字族、字重与尺度关系>",
      "palette": ["<十六进制色值>", "<十六进制色值>", "<十六进制色值>"],
      "traits": ["<可观察特征>", "<可观察特征>"],
      "source": "<候选文件的相对路径>"
    }
  ]
}
```

方向卡的**北极星 / 字体 / 色板 / 特征直接写进 manifest**,与画面一同展示。按情形加字段:

| 情形 | manifest 里加 |
| --- | --- |
| 固定画布的界面,不随宽度重排 | 顶层或候选里写 `"nativeViewport": "<宽>x<高>"`;对比页按该视口渲染再整体等比缩放,候选不自己写缩放;省略时用默认视口:桌面 1280×900、手机 390×844 |
| 自己写的可操作小样 | 候选加 `"interactive": true`(单个 HTML,脚本内联,不联网、不加载外部文件;浏览器存储在页面关闭后清空) |
| 项目里要运行起来才能看的页面 | 候选 `kind` 设为 `"url"`,用 `url` 指向**本机**开发服务器(只认 localhost / 127.0.0.1 / ::1),顶层用 `serve` 写下启动方式(命令 + 绝对 cwd + 地址) |
| 改动已有页面 | 把现状也放进来,加 `"baseline": true`——排在第一位,编号显示为「现状」,每轮至多一个 |
| 只有截图 | 候选 `kind` 设为 `"image"`(`source` 指向 PNG / JPEG / WebP) |

生成器契约:对比页 `connect-src 'none'`、不引用网络资源(interactive 候选才放开 script-src);候选及其引用的图片 / 字体 / 视频都放在 manifest 目录或其子目录里,用相对路径引用,生成器内嵌;manifest 写错时一次报出全部问题,旧的对比页不被改动;输出已存在时须加 `--force` 或换 `--output`;成功时 stdout 打印一行 JSON(`output` / `candidates` / `fingerprint` / `bytes`)。脚本不可用(未安装 / 运行失败)时按降级处理:把 manifest 与候选留给用户直接看,说明对比页还没组装,不临时另写一套工具。**判断文字大小和细节时必须用单张查看的「实际尺寸 100%」**——适应窗口的缩小图不算可读性通过。

### 5. 呈现与收敛

输出**诚实 tradeoff 表** + 比较器位置(文件路径)+ 键位说明,然后**停——选择权在用户**:

| # | 方向(名字) | 分歧轴 | 何时是正确选择 | 它的成本 |
| --- | --- | --- | --- | --- |
| 1 | 编辑排版 | 布局(分栏长文) | 内容以阅读为主导 | 竖向空间消耗大 |
| 2 | 工作台高密度 | 密度(紧凑多列) | 用户每天高频扫描操作 | 情感记忆度低 |

- 成本列诚实填写,不许全写「无」;不预设偏好,表里不暗夹推荐。
- 用户问「你选哪个」:基于产品人格与使用频率回答,不只答好看。
- 用户选定 → **keep 晋级**;用户要再来一轮 → **riff**(见下节)。

**选择回传**(无双向通信):对比页**不写回任何文件**、也不会自动给 Agent 发消息。用户点「选择」复制的是**一句话**,格式固定——`<轮次>：选 03 <方向名>`。用户粘贴这句话或直接说出选择后,按轮次和编号对照当前 manifest,确认是本轮的,把选择与备注更新进设计说明,再回到「实体化」之后的链路接着做。**禁止把页面上的推荐态当作用户选择**;只有用户明确说「你定 / 按推荐继续」才可按推荐方向推进,并在设计说明写明这是按授权推进而非用户亲自选择。

## keep / riff 语义

| 动作 | 行为 |
| --- | --- |
| keep `<方向>` | 胜者规格移入生产面 `ui/` 正式位置(新组件按需归并 `organisms/` 并核对命名),随后**删除探索面**;用户要求保留原型时显式记录保留决定 |
| riff `<方向>` | 保留比较器,围绕用户倾向方向的轴位再发散一轮新方向;上一轮落选方向弃置 |
| 未选择 | 停在比较器,不进入任何下游 draw-* / 正式实现 |

**认可选择的三选一证据**(进入下游 / 认定「用户已选」前必须有其一):① 用户在对话中粘贴或直接说出选择(格式见「选择回传」);② 用户在设计说明 / 备注中明确回复;③ 用户明确授权「你定 / 按推荐继续」。三条都不满足时停在比较器——**推荐态不是选择**,超时不自动推进、不倒计时。

**探索期间不运行 ui-graph**——`ui-graph generate` 默认递归扫描整个 `examples/ui-markdown/`,会把探索面卷进关系图;keep 晋级后再按常规对生产面跑 generate / diff-hash。

## 比较器 harness 规范(工具面)

比较器是**载体,不是选手**:切换条是工具 chrome,不做项目主题化(不用项目字体 / 品牌色 / 装饰阴影),在任何项目里外观一致——否则工具自身的样式会污染对方案的判断。行为契约如下,实现自研,语义固定:

- **键位**:数字键 `1`-`N` 与 `←`/`→` 切换方向,`R` 重放当前方向动效;焦点在输入框 / 多行文本 / 可选列表时忽略快捷键,按住修饰键时忽略。
- **焦点与可达**:切换条各项为按钮语义,恰好一项携带当前态标记(`aria-current="true"`);切换条可 Tab 到达。
- **持久化**:当前方向写入 URL 参数 `?v=<n>`,刷新 / 分享后仍在;首帧渲染完成(data-ready)前高亮不做初始定位动画。
- **切换零动画**:翻看是单会话上百次的高频动作,按频率法则方向切换**不得加过渡动画**;切换条自身的高亮滑动手感保留——那是对工具的反馈,不是对方案的动画。
- **重放即重挂载**:切换方向时重新挂载该方向(入场动效重放,看到的才是真实首帧);`R` 只重挂载不切换。
- **单方向全尺寸真语境**:每次渲染一个方向,全尺寸、带真实邻接内容(卡片有邻居、按钮有表单语境);禁缩略图九宫格——邮票尺寸判断不了间距与层级。
- **唯一允许的位置调整**:方向占据屏幕底部(dock / toast / 底部抽屉)时切换条移到顶部,其余样式不变。

## 探索面与生产面隔离

| 面 | 位置 | 规则 |
| --- | --- | --- |
| 探索面 | `examples/ui-markdown/prototypes/<slug>/`(规格 + 原型 organisms + 各方向预览 HTML + 比较器页,比较器命名 `preview_explore_<slug>.html`) | 只服务本次比较;可引用产物层 `token.md` |
| 生产面 | `examples/ui-markdown/ui/` + `examples/ui-markdown/organisms/` | 正式产物,唯一被下游 draw-* 与 ui-graph 消费的面 |

- **单向依赖**:探索面可引用生产面 token,生产面**禁止**引用探索面任何文件(不反向 import)——探索面组件未晋级前对下游不存在。
- **晋级即清理**:keep 后探索面默认删除;保留必须来自用户显式要求,且在 decisions 账本记录。
- **不混写**:探索面原型组件不得趁乱写进生产面 `organisms/`;晋级时按命名规范重新核对再归并。

## 约束汇总(硬性)

- [ ] 方向数默认 3、至多 5;每方向有名字与分歧轴,无两个方向共享同一轴位;任意两方向在明度轴或时代气质轴上取值不同
- [ ] 每方向一张方向卡:首轮 7 栏齐,入选方向补齐 16 栏;各栏写到规定程度(色彩 ≥ 三层 hex + 来源句;首屏骨架附 3–5 方框线框)

- [ ] 探索面 / 生产面单向依赖;keep 后删除探索面;保留需显式记录
